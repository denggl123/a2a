# 控制台国际化（i18n）

日期：2026-10-21。本文规定 A2N 节点控制台的国际化边界、消息表结构与推进路线。
适用于 `packages/a2n-sdk/src/a2n_sdk/web/`（控制台前端）与服务端面向用户的错误消息。

## 铁律

1. **协议字段与错误码永不翻译。** 跨节点互操作以英文枚举（`state`、`evidence_type`、
   `source` 等）与 `"CODE: 说明"` 格式的错误码为准。翻译只发生在呈现给人之前。
2. **消息表 key 是协议语义，不是文案。** key 形如 `state.SETTLED`、`evidence.receipt_unverified`，
   一个汉字都不许出现；文案只进值。这样加语言时 key 不用动，测试也不用重写。
3. **服务端错误消息保持 `CODE: 中文说明`。** 前端可拆前缀翻译说明部分；
   代码与测试只允许断言错误码，不允许断言消息文本（消息文本会随语言变化）。
4. **未知如实呈现。** 查表查不到就回退到原值或显式「未知」，不猜、不编、不留白。

## 结构

```
web/i18n.js            骨架：语言探测、text()/t() 取用、{name} 插值、双挂载（window 与 globalThis）
web/i18n.js 内 MESSAGES['zh-CN']   默认语言表（与历史版本逐字一致）
web/i18n.js 内 MESSAGES['en']      英文表（1325 / 1325；缺 key 仍自动回退中文，不会白屏）
scripts/i18n_check.py              消息表体检：缺键 / 死键 / 坏值 / 覆盖率（tests/test_i18n_table.py 调它）
```

取用约定：

| 调用 | 语义 |
|---|---|
| `I18N.text(key)` | 找到返回文案；找不到返回 `null`（调用方自行决定回退到原值或「未知」） |
| `I18N.t(key, vars)` | 找不到返回 key 本身；`vars` 做 `{name}` 插值 |
| `I18N.errorText(msg)` | 服务端「`CODE: 说明`」按码取译；**默认语言原样返回**（见阶段 2） |
| `I18N.locale()` | 当前语言（`localStorage['a2n.lang']` → `navigator.language` → 默认 `zh-CN`） |
| `I18N.locales()` | 可选语言清单 `[{id, label, keys, ready}]`；`label` 是**语言自称**，`ready` = 已有至少一条译文 |
| `I18N.setLocale(name)` | 切换语言（改内存 + localStorage + `<html lang>`，**不重渲染**；整页重载由页面的 `switchLocale()` 负责） |

加载顺序：`i18n.js` 必须先于任何界面脚本（`runtime.html` 第一个 `<script src>`）。
运行时自动把 `<html lang>` 设为当前语言；桩环境（Node vm）缺 `documentElement` 时跳过。

语言优先级是**显式选择 > 浏览器语言**：`setLocale()` 只改内存与 `<html lang>`，
不再走一遍探测 —— 否则用户点了「英文」，探测又按浏览器语言把它覆盖回中文
（这是骨架里真实存在过的 bug，阶段 2 顺手修掉并加了断言）。

## 阶段 1 迁移模式（每个文件照此办理）

0. **页面骨架先走 `data-i18n`**（仅 `runtime.html`）：静态标记的文案不写在标签里，
   写成 `data-i18n="键"` 且标签内容留空；属性文案用 `data-i18n-placeholder` /
   `data-i18n-title` / `data-i18n-aria-label` / `data-i18n-alt`。页面内联脚本的
   `localize(root)` 在启动时一次性填好：**查到才写，查不到保持原样**（不把键名
   甩给用户）。`localize()` 只做首屏，动态渲染的内容仍由各 `render*` 自己取词。

1. **先查验证链依赖**：`grep` 目标文件的中文文案是否被 `runtime_logic_check.js` /
   `node_console_check.js` / `tests/` 断言。锚定**渲染输出**的断言不用动（值逐字保留）；
   锚定**源代码形态**的断言必须同步改写为「代码引用 key + 消息表值逐字」双锚定。
2. **取值通道三选一**（按原语义回退行为）：
   - 原代码有兜底（`map[k]||value`）→ `I18N.text(key)`，`null` 时回退原值；
   - 一定存在（静态表内键）→ `I18N.t(key)`；
   - 带插值 → `I18N.t(key, {name: value})`，消息值里写 `{name}` 占位符。
3. **模板字符串拆拼接**：`'前缀'+v+'后缀'` 类改为占位符；三元 else 分支不许留裸引号
   （`:'+I18N.t(...)+'` 是语法错误，应为 `:I18N.t(...)`）。
   **嵌套模板慎用**：模板里再套 `` ${cond?`<br>${I18N.t(k)}`:''} `` 极易括号错配，
   优先提为中间变量再拼接（见 `experience.js` 的 `kept`/`review`）。
   **标签不许进消息值**：`<br>`、`<b>` 这类结构留在代码里拼接，
   消息值只放文字 —— `runtime_logic_check` 的「消息值不带 HTML」断言会拦下（`selection.js` 已踩过一次）。
4. **本文件不留展示文字**：连 `modeLabels` 这类小表也搬空，只留合法键名清单。
5. **补断言再跑验证**：新域至少补「一条逐字值 + 一条未知回退」；然后四层全跑。
6. **新旧逐字对比（推荐）**：迁完后用 `git show HEAD:<file>` 取旧文件，在 vm 里用同一组桩数据
   分别跑旧/新模块，比对渲染出的 `innerHTML`/`textContent`。输出长度相同且逐字一致才算没改语义
   （本次 `task-quality.js` 3746 字符、`points.js` 2219 字符、`forms.js` 14 组探针均零差异）。

### 已知边界

- **骨架里已经没有文案。** `runtime.html` 的静态标记只剩 `data-i18n` 键与空内容，
  `node_console_check.js` 里那些"页面上写着某句话"的断言仍然有效（渲染结果逐字一致），
  但**改文案只能改消息表**——直接改 HTML 会被「骨架不残留中文」断言拦下。
- **`localize()` 在首屏跑一次；切换语言走整页重载。** `switchLocale()` =
  `setLocale()`（落盘）+ 记住页签 + `location.reload()`；重载后骨架由 `localize()`
  重填、各模块按新语言重建。**「不追溯已渲染字符串」这条边界因此不存在了**——
  重载之后连已弹出的对话框、`notice`、模块加载时求值的表（如 `settlement.js` 的
  `methods`）都是新语言。代价是**正在填的表单会丢**，这是有意的取舍（见阶段 4）。
- **分类 / 维度 / 反馈方向的值是稳定 id。** `SKILL_CATEGORY` 的值是 `video`/`doc`/…
  而不是中文名（筛选状态里存的就是 id，加语言时状态不用迁移）；显示名走
  `catLabel()`/`facetTitle()`/`fbDirLabel()`/`upgradeLabel()`/`viewLabel()`，
  查不到就回显原值。改这些表时要同时改断言（`video-short → 分类 id 为 video`）。
- `node_console_check.js` 用 `addInitScript` 在**还没选过**时写入
  `localStorage['a2n.lang']='zh-CN'`，断言口径不受本机浏览器语言影响（英文表已 100%，
  英文浏览器现在会真的自动选英文 —— 不钉住它，中文断言的基线就随机器而变）。
- `node_console_check.js` 依赖 `playwright-core`（本机未装时用 `NODE_PATH` 指向含它的
  `node_modules`），且只接受**全新临时节点**；直接跑会因已有 8771 业务数据被拒。
  日常验证请用 `bash scripts/node_console_check.sh`，它自建临时 home 并在结束后清理。
- `settlement.js` 的 `methods` 表仍在模块加载时求值，存的是**文案**而不是 key。
  切换语言会整页重载，所以它现在的结果是对的；但这张表依旧是「加第三种语言要改代码」
  的地方。要彻底解耦就改成「存 key、显示时取词」，与 `catLabel()` 同一套做法。
- `business.js` 未被任何逻辑校验脚本加载（只在 `runtime.html` 里引入），它的等价性靠一次性
  新旧探针（34 组输出零差异）确认；`runtime_logic_check` 只断言消息表值与源码结构。
  下次改这块建议先补一条可复用的行为断言。
- `payment.js` 同属「只在页面里加载」：等价性靠一次性探针（31 组输出零差异，覆盖
  EARN/DEBT/PAY、upfront/authorization、免费与无共同方式、退款核对）。
  `payment.js` 的 `planMode()` 用 `switch` 而非前缀查表 —— 未知模式必须回 `undefined`
  （原文如此，界面显示空），不能回显键名。

## 阶段 2：服务端错误码（2026-10-22）

服务端面向用户的错误消息统一为 `"CODE: 中文说明"`。码是**协议的一部分**（跨节点互操作、
日志检索、前端按码取译都靠它），说明是**可以随语言变的那一半**。

- **全量覆盖**：`packages/` 与 `scripts/` 下 433 处中文 `raise`，379 个码（含阶段 0 的 19 处）。
  码名按域前缀：`BACKUP_*`/`RESTORE_*`、`COORD_*`、`P2P_*`、`RELAY_*`、`CARD_*`、
  `FEEDBACK_*`、`DISPUTE_*`、`MANAGEMENT_*`、`PRODUCT_*`、`PUBLIC_NODE_*`、`API_*` …
  三个脚本**明确排除**（`scripts/error_codes.py` 的 `EXCLUDE`）：`bootstrap.py` 是安装器
  进度输出（每行以 `✗` 开头，不是协议错误）、`docker_acceptance.py` 是验收断言、
  `error_codes.py` 是本脚本自己的帮助文字。排除项写在代码里，不靠口头约定。
- **登记表**：`docs/ERROR-CODES.md`，由 `python scripts/error_codes.py --write` 生成，
  按域分组列出「码 / 说明 / 出现处数」。手改会被测试拦下。
- **不变量由测试执行**：`tests/test_error_codes.py` 四条 ——
  没有中文 raise 缺码、码必须是大写 ASCII 蛇形、登记表与源码同步、覆盖
  `API_/MANAGEMENT_/PRODUCT_/RESTORE_/BACKUP_` 这几个真正面向用户的入口。
  校验也可单独跑：`python scripts/error_codes.py`。
- **前端按码取译**：`I18N.errorText(msg)`。默认语言（zh-CN）**原样返回**，
  一个字节都不改 —— 日志、截图、既有断言都不受影响；其它语言查 `err.<CODE>`，
  查到就用译文（**码仍留在前面**，便于排查），查不到回退服务端原文。
  接入点在 `runtime.html` 的 `request()`：所有面板的 `notice(e.message)` 自动受益。
- **`en` 表当时空着是刻意的**：一次性补 379 条英文译文没有校对者，写了也只是把中文
  换成另一种没把握的中文。机制先通、断言先立（`runtime_logic_check` 里造一条
  `err.BACKUP_CORRUPT` 译文验证取译路径），译文按域逐步补 —— 阶段 5 已补完，见下文。

### 阶段 2 的取舍（写下来免得后人猜）

- **一处码可以出现在多处**（`MOUNT_NOT_FOUND` 7 处、`PEER_TASK_CONTROL_UNAUTHORIZED` 5 处）：
  同一个语义就该是同一个码，前端才能只写一条文案。登记表里标注出现处数。
- **带参数的说明只译到码级**：`P2P_CARD_FOREIGN_OWNER: 不能替其他节点通告卡片：'did:…'`
  换成英文时只剩通用说明，参数细节丢失。要保留细节就得让服务端把参数结构化下发，
  那是协议改动，不在本次范围（已在 `errorText()` 注释里写明）。
- **协议封套不动**：`self._failure(sender, request_id, "RATE_LIMITED", "…")` 这类
  已经用 §7 错误码走结构化通道，不加 `CODE:` 前缀，否则码会被打印两遍。
- **错误码不是 HTTP 状态**：`COORDINATION-API §7` 的 `ERROR_HTTP` 表仍负责
  「码 → HTTP」，本次只补消息前缀，没有改任何状态码映射。
- **`coord_network.py` 的旧节点回退**原来靠 `"HTTP 404" in str(exc)` 判类型，
  现在先认 `COORD_HTTP_ERROR:` 前缀再认状态码 —— 说明文字将来翻译了也不会误判。


## 阶段 4：语言切换（2026-10-22，已完成）

先把「切了语言真的会变」这条链路打通，**不碰文案**（`en` 表仍是空的）。

- **入口**：`runtime.html` 头部 `#langWrap` 里的 `#lang` 下拉，选项来自
  `I18N.locales()`，标签用**语言自称**（`中文` / `English`）—— 界面已经是看不懂的
  语言时，用户得能认出自己那一行。选项值就是 locale id，不翻译。
- **只有就绪的语言才出现**：`ready` = 该表至少有一条译文。只有中文一份时整体
  `hidden`（点了界面一个字都不变的选择器，比没有选择器更糟）；补上 `en` 表第一条
  译文，选择器自动出现，**不用改界面代码**（阶段 5 补了 31 条，现在默认可见）。
- **切换 = 落盘 + 重载整页**（2026-10-22 改）：`switchLocale(name)` →
  `I18N.setLocale()`（内存 + localStorage + `<html lang>`）→ 记住当前页签 →
  `location.reload()`。重载后所有模块按新语言重建，骨架由 `localize()` 重填。
  最初做的是「原地重渲染、不 reload」，理由是 reload 会丢掉正在填的表单和当前页签；
  但**十几个模块各自在加载时按当时的语言一次性 `innerHTML`**（面板、表单、列表、
  首屏那张「开始使用这台节点」卡片都是），给每个模块补「语言变更就重渲染」必然漏，
  漏掉的那块就永久停在旧语言 —— 界面上半中半英，比不切更糟（补齐英文后截图里
  onboarding 卡片仍是中文，就是这么发现的）。两害相权：重载会丢表单，但不重载会
  交付一个假的双语界面。页签用 `sessionStorage['a2n.page']` 记住并只接受
  `find|sell|account` 三个值，重载后切回去，代价只剩「正在填的表单」。
- **没有复数形式**：`I18N.t()` 只做 `{name}` 插值，不做单复数。中文没有这个问题，
  英文会出现 "1 public nodes"。约定是**把数量放在冒号后面**（`Neighbours: {count}`、
  `Public nodes configured: {count}`），句子就不需要跟着数字变形；新写带计数的文案
  请沿用这个写法。要真正支持复数得给表加规则（`one`/`other`），是另一件事。
- **「不追溯已渲染的字符串」这条边界没有了**：重载之后整页重建，连弹窗和 `notice`
  都消失，不存在「留着旧语言」的东西。原地重渲染那一版才有这个边界。
- **验证**：`runtime_logic_check`（清单语义、自称、空表不出现、补译文后出现、
  「落盘 + 重载」且先记住页签、未知语言不落盘不重载、重载后首屏查表是英文）；
  `node_console_check` 走**真实下拉 + 真实重载**：两个选项、标题/按钮/动态面板/
  `<html lang>` 全变、模块自建的 onboarding 卡片也变、错误说明按码取译、
  刷新后仍记得、切回中文全部复原。

### 为什么不一次性补完 `en` 文案

1325 条界面文案 + 379 条错误说明，一次性写完没有校对者，就等于把中文换成另一种
没把握的中文。机制、断言、入口先就位，译文按域逐步补，每补一个域就能立刻在界面上
看到 —— 阶段 5 就是这么开始的。

### `err.*`：服务端错误说明（2026-10-22）

379 个码全部补上英文。这一批和界面文案不是同一套规则，原因值得写下来：

- **中文侧没有 `err.*`**。`errorText()` 在默认语言下原样返回服务端消息（一个字节都不改），
  所以表里不需要再抄一份中文。抄了反而多一个真相来源：服务端改了措辞，表里那份还是旧的，
  而且没人会去看它。
- **于是「其它语言必须是中文表的子集」对 `err.*` 不适用**。改为对照
  `docs/ERROR-CODES.md`（由 `scripts/error_codes.py` 从源码生成）校验码名 ——
  拼错一个码同样会被抓出来，而不是等到用户真的撞上那个错误、悄悄退回中文才暴露。
  `tests/test_i18n_table.py::test_error_translations_match_codes` 钉住这条，
  `scripts/i18n_check.py` 也把「界面文案覆盖率」和「错误说明覆盖率」分开打。
- **不做插值**。服务端已经把参数拼进原文（`账户不存在：acct-1`），`errorText()` 只按码
  查一句通用说明，再拼回 `码: 说明`。所以 `err.*` 的值里**不写 `{account_id}` 这类占位符** ——
  写了也不会被替换，只会原样显示给用户。代价是参数细节丢失（阶段 2 已记过这个取舍）。
- 验证：`runtime_logic_check` 直接用表里的真译文断言「码留在前面、说明换成英文」；
  `node_console_check` 在英文界面里真的调一次 `I18N.errorText('BACKUP_CORRUPT: …')`，
  确认浏览器里也换了。

### 一个被「覆盖率相关断言」掩盖的真 bug

补到第 6 批时，`runtime_logic_check` 的 `过半覆盖之后英文浏览器才自动切英文` 突然变红
（覆盖率 54.1%，自动选中的却是 `zh-CN`）。原因是 UMD 包装把 `factory()` 调用成
**没有参数**，而工厂里的 `detectLocale()` / `setLocale()` 都在用 `root.localStorage`
和 `root.navigator` —— `root` 在工厂作用域里根本不存在，两处都抛 `ReferenceError`，
又被各自的 `try/catch` 静默吞掉。后果是：

- 「记住上次选的语言」从来没生效过（写 localStorage 那一行同样抛错）；
- 「按浏览器语言自动选」也从来没生效过，永远停在默认语言。

这两条都在 `try` 里，界面上看不出来：切语言当场是对的（内存里的 `current` 改了），
只是刷新就丢。**断言之所以一直是绿的**，是因为当时覆盖率 45.1% < 50%，
`(enRatio >= 0.5) === (fullPick === 'en')` 两边都是 `false` —— 一条「按覆盖率算期望」
的断言在阈值一侧会退化成恒真。

修法是把 `root` 传进工厂（`factory(root)` / `function (root)`）。补了三条钉子：

- `切过语言会写进 localStorage`、`刷新后（重新 start）仍是上次选的语言` —— 逻辑层往返；
- `显式选择优先于浏览器语言` —— 存了 `zh-CN` 的英文浏览器不该被改回英文；
- `刷新后仍是英文`、`刷新后选择器回显上次选的英文` —— 浏览器层**真 reload** 一次。
  桩环境里取不到存储，这个 bug 只能在浏览器里验出来。

顺带修了测试自身的一个隐患：`node_console_check` 的 `addInitScript` 原来每次导航都
硬写 `localStorage['a2n.lang']='zh-CN'`，等于替用户把选择改回中文，刷新持久化永远
验不出来；改成只在「还没选过」时写（每次用一次性 profile，首次加载必然为空）。

- **`en` 必须是中文表的子集**：拼错一个键，那一条永远不生效而且没人发现。
  `tests/test_i18n_table.py` 把这条钉住了。
- **消息表体检工具**：`python scripts/i18n_check.py`
  - 缺键（代码引用、表里没有）→ 退出 1：界面上会直接露出 `rt.foo` 这种键名；
  - 死键（表里有、没人用）→ 默认提示，`--strict` 退出 1；
  - 值里有尖括号（HTML 必须留在代码里）、键里有汉字、其它语言不是中文表的子集 → 退出 1；
  - `--coverage` 只打各语言覆盖率。
  键名当**数据**传的地方（维度表第二列就是键名，再由 `I18N.t(label)` 取词）也算引用，
  否则会把 68 条活键误判成死键。
- **现状**：`zh-CN` 1325 / 1325（100%），`en` 1325 / 1325（100%）。
  未翻译的 key 一律回退中文，界面不会白屏、不会露键名。
- **回退的验收不挑具体键**：`node_console_check` 切到英文前，先在 `page.evaluate`
  里把 `rt.acct.connect_btn` 从 `en` 表**临时删掉**，读「连接」按钮必须仍是中文，
  读完立刻还原；`runtime_logic_check` 断同一件事。断言按「删掉 → 回退 → 还原」
  走，所以补到哪一批都不会变红 —— 早期版本拿「还没翻的某条键」当金丝雀，
  第 2 批翻完就红了一次，第 3 批又会红一次。
