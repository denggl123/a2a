# A2N 积分与兑换机制：设计要点

> 给协作者/AI 的约束文档。【已定】= 作者明确决定；【建议】= 讨论中提出、待作者确认。
> 未经作者确认，不要把【建议】当成既定事实，也不要突破"红线"。

## 0. 一句话

每个 agent 提供方发行**只对自己 agent 有效的服务额度（积分）**，别人愿意接受才能兑换。目的不是"买卖 agent"，而是**能力互换：我用你的，你用我的**。平台只记账、撮合、提示风险，不碰钱。

## 1. 红线（不得违背）

1. 【已定】平台不碰钱：不托管、不代收、不提供充值/提现入口、不设汇率。
2. 【已定】没有全局货币。积分 = 发行方对自己服务的承诺，价值全靠履约。
3. 【已定】积分只在**真实调用**发生时记入账户，不凭空发行，也不是"币"。
4. 【已定】信任由**每个对手方自己决定**（接受表）。平台不设等级、不设"多久才能做大单"的硬门槛，只给保守默认值并展示数据。
5. 【建议】积分只能换调用，不可提现（降低预付卡/代币类法律风险；正式上线前应咨询律师）。

## 2. 试用与锚定

- 【已定】agent 上架后，前 **10 次**调用免费，由卖家承担成本。目的：买家试用 + 产出真实案例与性能数据，作为价格锚点。
- 【已定】卖家可自调用，**不做单独隔离或标记**（换个身份就能绕开，隔离形同虚设）。靠**事后偏离度**识别：把试用期产出的样例/案例评分，与后续真实用户的评分、成功率、性能对比，偏离过大则该 agent 的样例可信度和信誉自动下降。
- 【已定】断线重新入网可再免费 5 次；【建议】仅在离线较久（如 24h+）时触发，避免惩罚家用电脑的短暂断线。
- 【已定】热门 agent 可关闭新用户免费入口，之后想用必须兑换或线下购买；【建议】做成旋钮（如每日 N 个名额），避免新人完全进不来。
- 【建议】试用期内价格锁定，涨价提前公示，历史价格对买家可见。

## 3. 接受表（核心）

每个人自己设：接受谁的积分、比例、持有上限、单笔/每日上限。对方没设，就不能兑。
【建议】新身份默认小额度，由对手方根据其履约记录自己调高。

## 4. 兑换撮合

- 【已定】**需求驱动**：只在"我想调用 B 的 agent，但手里只有 A"时触发；兑换与调用同一步完成，不囤币、不做投机交易。
- 【已定】**人人都是做市商**：以自己为中心，**最多三跳**寻路；也支持**三方循环易货**（A 要 B 的、B 要 C 的、C 要 A 的，各得所需）。
- 【已定】每一跳只要落在对方**被动接受表**内即合法，没人被迫接受没同意的比例，所以不存在"被坑"。
- 【已定】选**发起人总成本最低**的路径。
- 计价规则（各机器必须算出同一结果）：
  - 从目标倒推，每一跳按各自接受表折算；总成本由发起人承担，并可设上限。
  - 各跳比例乘积不必相等，用统一规则处理零头：最小记账单位，统一向上取整（付款方多付）。
  - 平局依次比：跳数少 → 履约记录好 → 节点 ID。
- 找不到路径时，界面说明原因并给替代方案（直接购买、发布挂单），不要只显示失败。

## 5. 原子性（预签约定包，思路同 HTLC/两阶段提交）

1. 发起人签**约定包**（每一跳、金额、截止时间）发给链上所有人。
2. 每人预留额度并签回确认（ack）。
3. 全员 ack 后约定包生效；任何人凭"发起人签名 + 全员 ack"即可推进结算，**发起人断线不影响**。
4. 到期未凑齐（如只发到一家就断线）→ 整体作废，预留自动释放。
5. 【已定】生效后逐跳结算，每跳双方互签收据；若最后一跳有人下线，已完成的跳保留，失败跳及其后作废。
6. 【建议】截止时间短（几分钟）；限制每人同时挂起的预留数；时间以"发起人签发时间 + 固定时长"为准。

**保证范围**：账目一致（不会两家动了一家没动、不会被换成没同意的比例）。**不保证**服务质量与对方履约，不得对用户承诺"绝对不出错"。

## 6. 信誉与防刷

- 【已定】优胜劣汰：多维度指标（成功率、延迟、网络参数、与样本差异、复购），双边记录评价；已使用者的低评价不会被刷分抹去。
- 【已定】发现范围是"自己需要的部分"，不是全量市场、没有全局大奖，所以刷分收益低，**暂不专门设计防刷机制**。
- 【已定】换马甲不是重点问题（反而说明服务有价值）；看"回头率"比看"新身份数"可靠。
- 【已定】**样例 vs 真实使用的偏离度**是核心信号：样例评分与后续真实用户评分差得越大，越可疑。【建议】偏离度需要足够的真实样本才生效（早期只显示样本数，不下结论）；小样本用平滑处理。
- 【建议】评价展示时区分付费的 / 试用期的，并显示独立评价人数。

## 7. 真币（平台之外）

- 【已定】卖家可给自己的积分标**参考单价**；买家线下付款，卖家手动加积分。平台不管钱，只提示风险，并提示"也可通过市场兑付"。
- 【已定】真币的作用是给积分一把**公共的尺子**，避免各家积分互相比价导致价值失真。买多了的人可以兑付给别人（对方愿意收才行）。
- 【已定】发行方可随时停止发行（此后只能靠购买/兑换获得其积分）；持有者风险自担。
- 【建议】界面不出现"充值"按钮和法币成交价字段；措辞用"参考价""联系发行方购买"；写明"钱款往来不受平台保护"。

## 8. 应展示的信息

标价 vs 市场实际成交比率（差距 = 信用信号）；履约记录（交付数、成功率、延迟、在线时长）；【建议】"已发出未使用"数量对比日均产能。

## 9. 容易走偏的地方（AI 请注意）

- ❌ 不是代币/交易所：没有全局币、没有囤币交易、没有投机。
- ❌ 不是平台定价或平台发额度：信任额度由对手方自己给。
- ❌ 不是"充值购买"产品：平台无收款入口。
- ❌ 不是做市商赚差价：三方环里每人各得所需。
- ❌ 不要设计复杂的防刷/反女巫系统或全局排行榜。
- ❌ 不要一上来实现多币种多跳自动兑换（见分期）。

## 10. 分期（【建议】）

1. **一期**：试用 + 单卖家额度 + 双边记账 + 两方直接互换（互欠自动抵消）。
2. **二期**：接受表 + 一跳兑换。
3. **三期**：三跳寻路、三方环、参考价/成交价展示。

## 11. 未决问题

积分可否转让给第三方？发行方停发后已持有积分如何处理？调用失败但已扣积分的纠纷谁裁决？接受表默认值取空还是保守值？

## 12. 优先级提醒

以上全是纸面设计，网络里尚无真实交易。**先验证核心假设**：找 5～10 人各上架 1～2 个真实可用的 agent，只开"直接互换"，看是否会互相调用并回头再用，再决定投入多少在兑换网络上。
