# A2N 积分与兑换机制：设计要点

> 给协作者/AI 的约束文档。【已定】= 作者明确决定；【建议】= 讨论中提出、待作者确认。
> 未经作者确认，不要把【建议】当成既定事实，也不要突破"红线"。
>
> 2026-10-08 规则澄清：服务发行增加供应方持有的自家积分；主动加分增加指定使用方持有的供应方积分。前十次样品由业务层跳过结算；积分是支付协调调用的独立支付子模块。本轮已实现模块，具体接口与实施规则见 [服务积分支付模块](POINTS.md)；本文件继续记录作者规则与建议的区别。

## 0. 一句话

每个 agent 提供方发行自己的积分。**供应方提供真实服务后，按其开放的发行规则增加供应方自己持有的自家积分**，表达其已经产出的服务价值；供应方也可主动向使用方加自己的积分。其他使用者是否接受、按什么比例接受，由他们自己决定。目的为**能力互换：我用你的，你用我的**。平台只记账、撮合、展示履约信息，不替任何一方规定积分价值。

### 0.1 发行方与持有方

积分必须同时标明“谁发行”和“谁持有”，不能用一个不带发行方的总余额表示。

| 场景 | 积分发行方 | 增加余额的账户 | 业务含义 |
|---|---|---|---|
| A 提供真实服务，适用服务发行规则 | A | A 持有的 A 积分 | A 通过实际服务产生自己的积分，后续可向愿意接受的人兑换服务 |
| A 主动给 B 加积分，例如双方约定的线下购买 | A | B 持有的 A 积分 | B 获得 A 的积分，可使用或按对方接受条件兑换 |
| A 的 Agent 交付前十次样品 | 无发行事件 | 无结算余额变动 | 只记录业务交付和公开样品，跳过所有结算 |

【已定】供应方可配置允许“免费调用后增加供应方积分”或“使用方欠账”等模式。是否同时记录使用方欠账，取决于双方接受的模式，不能把每次供应方积分增加自动解释成使用方负债。具体借贷分录尚见第 11 节。

例如 A 提供服务并按约定发行 10 个 A 积分，增加的是 **A 自己持有的 A 积分**。C 愿意接受 A 积分时，A 才能按 C 的接受条件兑换 C 的服务；服务发生本身不替 C 作出认可决定。

## 1. 红线（不得违背）

1. 【已定】平台不碰钱：不托管、不代收、不提供充值/提现入口、不设汇率。
2. 【已定】没有全局货币。积分 = 发行方对自己服务的承诺，价值全靠履约。
3. 【已定】发行有两条路径：**真实服务触发供应方取得自家积分**，以及**供应方主动向指定使用方加自家积分**。二者分别记录来源和授权；第一条不能被改成“供应方取得使用方发行的积分”。前十次样品不触发任何发行或其他结算。
4. 【已定】信任由**每个对手方自己决定**（接受表）。平台不设等级、不设"多久才能做大单"的硬门槛，只给保守默认值并展示数据。
5. 【建议】积分只能换调用，不可提现（降低预付卡/代币类法律风险；正式上线前应咨询律师）。

## 2. 试用与锚定

- 【已定】agent 上架后，前 **10 次**服务免费，由卖家承担成本，并强制形成公开脱敏样品。目的：买家试用 + 产出真实案例与性能数据，作为价格锚点。
- 【已定】前十次样品**跳过任何结算**：不扣积分、不增积分、不记支付欠账、不兑换、不转账。业务模块判定样品资格并直接完成免费接单、调用、样品与反馈流程；此流程不进入支付协调的结算流程，也不调用任何支付子模块。
- 【已定】卖家可自调用，**不做单独隔离或标记**（换个身份就能绕开，隔离形同虚设）。靠**事后偏离度**识别：把试用期产出的样例/案例评分，与后续真实用户的评分、成功率、性能对比，偏离过大则该 agent 的样例可信度和信誉自动下降。
- 【已定】断线重新入网可再免费 5 次；【建议】仅在离线较久（如 24h+）时触发，避免惩罚家用电脑的短暂断线。
- 【已定】热门 agent 可关闭新用户免费入口，之后想用必须兑换或线下购买；【建议】做成旋钮（如每日 N 个名额），避免新人完全进不来。
- 【建议】试用期内价格锁定，涨价提前公示，历史价格对买家可见。

### 2.1 分层与隔离（【已定】）

```text
业务层：资格、前十次样品、供给定价、接单、Agent 调用、交付与反馈
  ├─ 前十次样品：直接走免费业务流程，跳过结算
  └─ 需要支付或积分记账的普通服务：提交已授权的结算意图
       ↓
协调层 / 支付协调：共同能力、条件协商、计划、方法选择、执行编排与恢复
       ↓ 通过统一支付端口调用
独立支付子模块：原生币 ｜ x402 ｜ 积分（发行、持有、接受表、兑换、欠账）
```

| 责任边界 | 负责 | 输入与限制 |
|---|---|---|
| 业务模块 | 是否结算、是否样品、服务价格、实际交付事实 | 保存免费原因和调用事实；样品不创建结算订单，不以“零金额积分支付”替代跳过 |
| 支付协调 | 协商和选择双方接受的支付方法，固定计划，调用子模块，汇总和恢复结算状态 | 接收业务授权；不会自行决定试用资格，也不会替业务执行 Agent |
| 原生币 / x402 子模块 | 各自的提交、验证、查询及退款规则 | 不读取样品槽位或试用计数，不自行选择业务价格 |
| 积分子模块 | 本方法的发行规则、分账户账本、接受条件、兑换、欠账及恢复 | 服务发行须绑定业务提供的原交付事实；主动加分须绑定供应方授权。不判断前十次，不调用 Agent，不改动其他方法的账本 |

【已定】“免费但产生供应方积分”适用于供应方开放的普通服务模式，仍需由业务发起积分记账；它与“前十次跳过所有结算”的样品流程是两个明确的业务条件。不能仅根据价格为零判断是否绕过支付协调。

逻辑隔离通过模块接口实现，可沿用同一个节点身份、加密存储和进程。每种方法保存自己的记账事实，协调层保存方法与原计划的绑定，业务层读取结算结果用于交易展示。查询或恢复结算不能重新执行 Agent，重复通知不能重复发行、扣款或记欠账。

### 2.2 当前实现状态

业务资格、样品报价、接单与执行已拆到节点 `TradeService`，原 `PaymentService` 保留兼容 API 与支付通道装配。积分由 SDK `PointsBook`、`PointsCoordinator` 及节点 `PointsNode`、`PointsPayment` 实现。原生币、x402 与积分使用独立方法账本，统一关联原业务事实；首十次免费流程不会创建结算报价、订单或积分事件。实现与验证见 [积分模块](POINTS.md)。

## 3. 接受表（核心）

每个人自己设：接受谁的积分、比例、持有上限、单笔/每日上限。对方没设，就不能兑。
【建议】新身份默认小额度，由对手方根据其履约记录自己调高。

【已定】供应方给自己的 Agent 定价；使用方决定认可哪些积分及其兑换比例。供应方涨价不会自动改写已有积分余额、其他节点的接受表或已接受交易的条件；后续兑换按各方届时接受并固定下来的条件进行。

## 4. 兑换撮合

- 【已定】**需求驱动**：只在"我想调用 B 的 agent，但手里只有 A"时触发；兑换与调用同一步完成，不囤币、不做投机交易。
- 【已定】**人人都是做市商**：以自己为中心，**最多三跳**寻路；也支持**三方循环易货**（A 要 B 的、B 要 C 的、C 要 A 的，各得所需）。
- 【已定】每一跳必须落在对方**被动接受表**内，没人被迫接受未同意的积分或比例。接受条件表达各方认可，不保证服务质量或绝对公平。
- 【已定】选**发起人总成本最低**的路径。
- 计价规则（各机器必须算出同一结果）：
  - 从目标倒推，每一跳按各自接受表折算；总成本由发起人承担，并可设上限。
  - 各跳比例乘积不必相等，用统一规则处理零头：最小记账单位，统一向上取整（付款方多付）。
  - 平局依次比：跳数少 → 履约记录好 → 节点 ID。
- 找不到路径时，界面说明原因并给替代方案（直接购买、发布挂单），不要只显示失败。

## 5. 多方结算与恢复

【已定】三方交换按**同一笔交易整体成功**。网络中断时各节点可以暂时处于不同进度；恢复后核对原交易并回正。不得把“前面几跳永久成功，后面几跳作废”作为最终结果。

以下是实现约束。本轮采用持久化的准备、唯一整体决定与应用分录协议；全员准备后还需要发起节点持久化决定，再由各方验证和幂等应用。不能仅凭“全员 ack”声称完成结算。

1. 全体参与方接受同一个约定包，固定交易 ID、积分发行方、持有方、每一跳金额、条件版本、有效期及签名。
2. 每人先预留自己的额度，持久化原约定与准备记录，再签回确认。预留不作为已完成转账。
3. 同一约定只能产生一个可验证的整体决定：提交或中止。提交凭据须证明所有必要参与方已接受原条件；各方最终记录相同的决定。
4. 尚未形成整体提交时，只有确认整体中止后才能释放相关预留。单纯超时、未收到响应或某节点离线不能证明其他节点没有形成提交凭据；无法确定时保留待核对状态。
5. 已形成整体提交后，各方以原交易 ID 幂等补齐本地分录与收据，直到全体对账一致。响应丢失、节点重启或最后一跳离线均不能把整笔交易改成部分结算，也不能另造交易再扣一次。
6. 【建议】采用持久化的准备、整体决定、应用分录、对账阶段，限制同时挂起的预留数和协议有效期；具体决定凭据、失联恢复及中止证明列入积分模块的协议设计。

**保证目标**：最终账目一致、各方按已接受条件结算、原交易不会重复扣款。网络分区时可以等待恢复，不能同时承诺所有节点立即完成。付款结果与服务质量分别记录；积分模块不裁定服务是否“绝对公平”。

## 6. 信誉与防刷

- 【已定】优胜劣汰：多维度指标（成功率、延迟、网络参数、与样本差异、复购），双边记录评价；已使用者的低评价不会被刷分抹去。
- 【已定】发现范围是"自己需要的部分"，不是全量市场、没有全局大奖，所以刷分收益低，**暂不专门设计防刷机制**。
- 【已定】换马甲不是重点问题（反而说明服务有价值）；看"回头率"比看"新身份数"可靠。
- 【已定】**样例 vs 真实使用的偏离度**是核心信号：样例评分与后续真实用户评分差得越大，越可疑。【建议】偏离度需要足够的真实样本才生效（早期只显示样本数，不下结论）；小样本用平滑处理。
- 【建议】评价展示时区分付费的 / 试用期的，并显示独立评价人数。

## 7. 真币（平台之外）

- 【已定】卖家可给自己的积分标**参考单价**；买家线下付款，卖家手动加积分。平台不管钱，只提示风险，并提示"也可通过市场兑付"。
- 【已定】真币的作用是给积分一把**公共的尺子**，避免各家积分互相比价导致价值失真。买多了的人可以兑付给别人（对方愿意收才行）。
- 【已定】发行方可随时停止发行（此后只能靠购买/兑换获得其积分）；持有者风险自担。
- 【建议】界面不出现"充值"按钮和法币成交价字段；措辞用"参考价""联系发行方购买"；写明"钱款往来不受平台保护"。

## 8. 应展示的信息

标价 vs 市场实际成交比率（差距 = 信用信号）；履约记录（交付数、成功率、延迟、在线时长）；【建议】"已发出未使用"数量对比日均产能。

## 9. 容易走偏的地方（AI 请注意）

- ❌ 不是代币/交易所：没有全局币、没有囤币交易、没有投机。
- ❌ 不是平台定价或平台发额度：信任额度由对手方自己给。
- ❌ 不是"充值购买"产品：平台无收款入口。
- ❌ 不是做市商赚差价：三方环里每人各得所需。
- ❌ 不要设计复杂的防刷/反女巫系统或全局排行榜。
- ❌ 不要一上来实现多币种多跳自动兑换（见分期）。

## 10. 分期（【建议】）

1. **一期**：试用 + 单卖家额度 + 双边记账 + 两方直接互换（互欠自动抵消）。
2. **二期**：接受表 + 一跳兑换。
3. **三期**：三跳寻路、三方环、参考价/成交价展示。

## 11. 未决问题

本轮具体采用的实施规则：已有积分支付仅转移余额；主动加分明确选择新发行或存量转移；免费增积分不记使用方欠账，DEBT 模式另记已授权欠账并受供应方上限约束；接受表默认为空；停发保留原积分与已接受交易。整体提交及失联恢复见 [实现协议](POINTS.md)。这些选择保持显式，后续改动需要新规则与兼容处理。

后续仍可讨论：是否开放脱离服务的单独转让；是否增加已有积分支付同时发行的新模式；长期停服时积分持有方如何协商；是否为新身份提供接受表建议值。当前不设全网裁决者，质量异议沿用双边协商与信誉机制。

这些细节不能通过假设更换第 0 节已确认的发行对象，也不能把第 2 节样品资格下放给积分模块。

## 12. 优先级提醒

**积分发行与兑换已进入实现及本机多节点验证**，原生币与 x402 保留本地私有链验证。仍需验证真实用户的核心假设：找 5～10 人各上架 1～2 个真实可用的 agent，从直接互换开始，看是否会互相调用并回头再用，再决定如何发展兑换网络。
