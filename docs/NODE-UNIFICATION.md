# 节点业务统一迁移

日期：2026-10-05。产品只有 `Daemon → NodeRuntime → LocalStore(runtime.db)` 一套业务装配。每个节点同时是买方工作台、卖方市场与公共发现节点。

## 迁移范围

| 原能力 | 统一后的落点 | 处理 |
|---|---|---|
| 卡片形状、整卡哈希、节点身份验签 | SDK 卡片规则 + 节点签名适配器 | 保留规则，移除平台注册表依赖 |
| 模板偏差、客观验收 | 验收库 + `DeclaredAcceptance` | 保留可复算算法 |
| 上架、暂停、下架、稳定商品身份 | `RuntimeManagement`、本机供给投影 | 直接管理本节点公共供给 |
| 发现、收藏、任务与幂等、晚到结果、取消 | 协调服务、`NodeRuntime`、`CallService` | 唯一业务链 |
| 前十次免费履历、隐私投影 | `TrialBook`、公共样品 | 统一真实交付账本 |
| 双向反馈、版本链、轻量争议 | `FeedbackBook`、`DisputeBook`、互签收据 | 保留已有节点实现 |
| 客观表现／质量偏差／使用评价分开展示 | 节点质量事实投影 | 从本机调用和已验证反馈派生 |
| 币种精度、整数计价、可插拔结算 | SDK 计价与结算端口 | 迁移纯规则；真实支付驱动单独接入 |
| 集中注册、中央任务池、平台反向隧道、演示充值与仲裁退款 | — | 删除旧业务装配及专属接口 |
| `SovereignNode`、演示脚本和独立演示控制台 | — | 删除，测试运行同一节点 Docker 镜像 |

旧数据库、节点卷和原有身份不在源码清理范围内。旧中央库的资金余额不会被解释为新节点的可支付余额。

## 公共义务

基础协调始终提供。每个在线节点接受有界的签名握手、查找、分页引荐、取卡和元数据探测。节点保存并介绍已验证、未过期的公共邻居及供给事实，协助其他节点逐级发现。网络维护不调用 Agent。业务接单、公开样品、见证和任务中继分别管理，不能用业务下架关闭基础发现。

## 验证要求

使用同一 Docker 镜像运行相互独立的节点和持久化卷，通过正常管理接口挂载 HTTP/A2A Agent 并上架。验证逐级发现、暂停续查、导入与刷新、真实调用、重复调用不重复执行、验收失败、前十次样品、双向反馈、争议与撤回、公共服务保护、节点重启和下架。

测试报告记录实际环境和每个检查的结果。Docker 桥接网络不能证明真实跨公网、不同 NAT 和长期运行容量已通过。
