# A2N 产品定义（对齐稿）

> 上位文档 → [`VISION.md`](VISION.md)（最高愿景）。本文只回答"产品长什么样"。
>
> 只讨论三件事：**产品最终长什么样、设计哲学、用户体验**。不涉及任何实现。

---

## 一句话（修订）

原文：*"让全世界每一台闲置的电脑，都能变成一台自动接单、自动交付、自动记账的 agent 摊位。"*

这句只说清了**供给**，没说清**用户为什么敢用**。建议改为主副两句：

- **主句（定义）**：让每一次交换都不需要中间人——**你的电脑既是摊位，也是你的账本。**
- **副句（对外）**：装一次，你的电脑开始自己接单、自己交付、自己记账。**账本在你手里，谁也不需要被信任。**

改动理由：原句里的"摊位"是供给侧语言，而产品的不可替代性在"账本在你手里"。
把这两件事并排说出来，用户才知道自己得到的不只是"能赚钱"，而是"不必相信任何人"。

# 第一部分：产品最终长什么样

## 1.1 它由两个物件和一张脸组成

| | 是什么 | 用户对它的说法 |
|---|---|---|
| **摊位** | 我提供什么、什么价、什么时候可以接 | "我在这儿卖东西" |
| **账本** | 我干过什么、谁签收了、结了多少、对方认不认 | "这是我的账" |
| **一张脸** | 一行状态 + 一句话入口 | "我电脑在忙什么 / 我要用一句话下单" |

装完之后，用户能看到的就是这三样，**没有第四个东西**。
原文档里"账本"和"三种身份"都写到了，但"摊位"作为产品里的一个实体没有被点出来——
它是手艺人的落点，也是"我的电脑到底在卖什么"这个问题的答案。

## 1.2 一张脸，同时服务三种人

不是三款产品、三套界面，而是**同一个首页的三种用法**。首页只有两样东西：

```
┌─────────────────────────────────────────────┐
│  在忙 · 今天 3 单 · 收入 12.5                │   ← 一行状态
├─────────────────────────────────────────────┤
│  说你想做什么…                        [ 发出 ] │   ← 一个输入框
└─────────────────────────────────────────────┘
                          （点状态 → 我的摊位 / 我的账本）
```

| 身份 | 他在这张脸上做的唯一一件事 | 停留时间 | 成功的样子 |
|---|---|---|---|
| **挂机者** | 什么都不做，只偶尔读那一行状态 | 几秒钟 | 一个月后打开，看见一笔收入 |
| **使用者** | 用输入框说一句话 | 一句话的时间 | 结果回来，且他知道能验证 |
| **手艺人** | 从状态里点进"我的摊位"，摆一次 | 一次性、可中断 | 第二天醒来有陌生人的签收 |

**为什么这样切**：三种身份的差别不在界面，在**停留时间**。
任何让挂机者必须做选择的首页，都会把最大的一类人挡在门外。

## 1.3 产品的四个稳定状态（比"功能列表"更重要）

| 状态 | 触发 | 界面 | 占比 |
|---|---|---|---|
| **安静** | 没活儿 | 什么都不显示 | 绝大多数时间 |
| **在忙** | 有任务在跑 | 图标极轻地动一下（全产品唯一的动效） | 少数 |
| **有话说** | 他必须知道的事：第一笔收入、账本验不过、密钥该备份了 | 亮一次，说完就回到安静 | 极少 |
| **异常** | 凭证对不上、对方赖账 | **绝不沉默**，但只对当事人说，且必须给出"你自己能查什么" | 罕见 |

**安静是默认态，也是承诺。** 一个"装完即消失"的产品，它的界面预算几乎全部花在"有话说"和"异常"这两个状态上。

## 1.4 打扰预算（把"不打扰"变成可执行的数字）

原文档说"不弹窗、不打扰"，又说"第一次被发现""第一笔收入"要让用户看见——这两件事是冲突的。解法是给打扰一个额度：

- **安装后 24 小时内：允许 2 次主动出现。** 一次是"有人在网络里"，一次是"你的电脑收到了第一笔签收"。
  （口径：界面文案不说"赚"——没签收的不许叫收入，签收了的说"收到了"就够。）
- **此后：只有"异常"可以主动出现，一事一次。**
- **永远不允许**：更新提示、活动提示、运营提示、别人赚了多少。

这条额度必须写死。它不是克制，是**产品定位的证明**：不靠注意力赚钱的东西，才被允许不打扰。

## 1.5 它是什么形态，不是什么形态

**是**：桌面上的一个图标，点开是本机的一个页面。

**不是**：不是网站、不是账号后台、不是订阅服务、不是浏览器插件。

原文档在"小图标"和"打开一个页面"之间来回，需要说清这一点：
**那个页面是本机的，不是云端的。** 断网、断源、平台消失，这个页面照样能打开、账照样能看、凭证照样能验。

它也没有"我的主页""粉丝""动态""等级""积分商城"——它不做身份表演，只做交换。

## 1.6 "没有平台"要说得住：没有中心权力

对外不要再笼统说"没有平台"——这句话会被现实戳穿。说得住的版本是：

> **没有中心权力**：没有任何一方掌握你的钱、你的身份、你的账本，或"你能不能参加"。

- 存在会合与寻址这样的**公共设施**（像路灯），但它不是生意；
  它不参与任何一次交换、不知道你在卖什么、收了多少、交付了什么。
- 它不可以是"我们顺便开的那个入口"。**一旦某个角色既能决定你被不被看见、又能从中收费，中间商就回来了。**

这条界线是产品定义里最容易被自己突破的地方，也最难回头。

### 1.6.1 节点角色模型（2026-09-25 拍板）

"没有中心权力"落到节点上，是一套明确的角色划分：

| 角色 | 是什么 | 谁来当 |
|---|---|---|
| **普通节点** | 装了 SDK 的每台电脑：一个身份、自己的供给、自己的调用记录、与对手方的互签收据 | 默认，人人都是 |
| **全功能控制台** | 每个节点自带：控制自己（找/卖/我的账户/行情/收据对账）+ 读网络公开事实。**只能控制自己**——别人的供给开关只在别人的控制台上 | 随节点自带 |
| **发现节点** | 额外承担全网目录存储与 gossip 路由。理论上任何节点都能当、没有门槛，但一般不当（带宽/存储/常驻在线是持续成本） | 可选角色 |
| **平台** | 把"发现节点 + 公证（中继、行情、刻章）"角色**常开化**的那台机器。连不连是每个节点的自由，断开之后节点自己站得住 | 自愿常开的公共设施 |

一句话：**装 SDK = 一个普通节点 + 一个全功能控制台**。"全量"这个词只属于发现节点——
它描述的是承担了多少网络角色，不是某台电脑的等级。

## 1.7 "赚钱"必须被诚实定义（最重要的未决问题）

产品定义里最容易含混过去、也最致命的一处。必须分三层说，不许混：

| 规模 | 用户得到的东西 | 产品里怎么称呼它 |
|---|---|---|
| 2 台电脑（同一 Wi-Fi） | **没有钱，也有用**：互相干活、互相记账、互相验证 | "交换" |

第一层的对账机制（已实现，写死口径）：**自持结算 = 双边互签收据**。每笔交付完成时，
调用方与供给方在同一份凭证上互相签名，双方各存一份；对账就是两两核对签名与口径——
同一 `task_id` 对出来一致即清。**没有托管就没有增发，所以不存在一本需要全网对齐的总账**；
"必须有一本总账"这个需求本身被消掉了，这正是"没有服务器也能成立"的根本原因。
| 网络小 | 账面等价物：谁欠谁多少，且这个"欠"能被凭证证明，可转让 | "债权" |
| 网络大 | 真实需求方带着钱进来，钱只经由用户自己的通道进出，产品不保管 | "收入" |

**绝不能出现"你的电脑在赚钱"，而账上其实是一串平台发的积分。**
要么老老实实说"你的电脑在攒债权"，要么就真的能变成钱。这一条决定这个产品是
"一个交换网络"，还是"一个讲故事的庞氏"。

## 1.8 终态画面（补全）

原文档的终态是"全球 agent 劳动力市场"。补三句让它可判定：

1. **有无数摊主，但没有一个货架。** 需求方提条件，满足条件的摊主自己浮上来；
   没有人能买到一个更好的位置。
2. **没有客服、没有仲裁员、没有运营**——这不是省钱，是产品的形状：
   规则一致地适用于所有人，所以不需要人去解释和例外处理。
3. **交易数量增长时，产品的界面不增长。** 一亿笔和一笔记在账本里长得一样；
   如果规模变大就要加功能、加页面、加运营，说明产品没做对。

# 第二部分：设计哲学（从 5 条口号改成 6 条判据）

原则不是用来欣赏的，是用来**否掉需求**的。每条给出：判据 / 它会否掉什么 / 最容易犯的错。

## ① 等价交换，而非信任

- **判据**：任何需要用户"选择相信"的界面元素，都必须能被替换成"你自己看"。
- **否掉**：平台担保、官方认证、已审核、优选、金牌。
- **最容易犯的错**：把"验证"做成仪式性的绿勾。绿勾必须能落到**具体那一笔**——
  点下去要看得见"哪条凭证、谁签的、签的是什么"。**看不懂的验证，等于没有验证。**

## ② 每台电脑都是一个审计师

- **判据**：账本的第一读者是用户本人；产品的消失不改变任何一条记录的效力。
- **否掉**：任何"必须先连上谁才能看到自己的账"的设计。
- **最容易犯的错**：**只做了真相，没做解释。** 用户要的不是一串校验值，是
  "这笔是什么、跟谁、什么时候、多少钱、对方认不认"。真相是给会验的人看的，
  解释是给所有人看的——两者都要，且顺序不能颠倒。

## ③ 接入成本趋近于零

- **判据**：从"下载"到"我的电脑在为我工作"之间，不允许存在第二个必须做出的决定。
- **必须诚实划的一刀**：这条铁律约束的是**"加入网络"和"一句话下单"**，
  **不约束"摆摊"**。摆摊本质是一次创作（卖什么、多少钱），不可能零成本；
  它必须是**可选的深度**，而不是进门门槛。
- **最容易犯的错**：把可选深度放到第一屏，用"完善你的资料"把挂机者吓跑。

## ④ 网络应该像空气

- **判据**：界面里不出现"连接中、在线、离线、地址、同步"这类词——
  除非它直接导致"我的结果还没来"。
- **否掉**：拓扑图、网络状态面板、节点列表作为主界面。
- **最容易犯的错**：把"第一次被发现"做成一张酷炫的星图。它让用户兴奋五秒，
  第六秒让用户以为"这东西要配置网络"。
  那一刻要给的实感是**"有别人"**，不是**"有网络"**：
  给"三个邻居，其中一个刚接了个活"，不给拓扑。

## ⑤ 小网络也要有用，大网络也不必存在

- **判据**：两台电脑之间必须存在一个完整、能讲清的故事：互相干活、互相记账、
  互相验证。**某个功能在两台电脑时毫无意义，它就不是核心功能。**
- **否掉**：以"生态"为前提的一切——排行榜、热门、精选、社区、达人。
- **最容易犯的错**：用"以后会有很多节点"来给今天说不清价值的东西找理由。

## ⑥ 不打扰是一种承诺，不是一种偏好（原文档缺，但必须有）

- **判据**：任何主动出现的界面，都要回答"用户此刻不处理，会有什么真实损失"。
  答不出来，就不许出现。
- **否掉**：推送、红点、更新提示、"你的邻居在等你"。
- **这条要经得起最赚钱的诱惑**：假如"给热门摊位一个推荐位"能显著提高收入，
  依然不能做——因为它是注意力生意的第一步。**不做注意力生意这件事，
  必须在一个能赚钱的岔路口上被拒绝过一次，才算真的。**
- **沉默是资产**：产品越沉默，开口时越重。所以"异常"那一次必须说得极清楚。

# 第三部分：用户体验

## 3.0 一条弧线（六个时刻不是六个功能，是一条从怀疑到拥有的弧线）

```
沉默的承诺 → 有人在 → 有收入 → 有结果 → 有底气 → 有生意
   敢不敢装      敢不敢留        敢不敢用        离不开
   ├──────── 前三步解决"敢不敢" ────────┼──── 后三步解决"离不开" ────┤
```

每个时刻都要同时满足三件事：**用户做了什么（≤1 步）、他必须看懂什么、他此刻的情绪是什么。**
三件事缺一个，这个时刻就白做了。

## 3.1 六个时刻（+ 三个原文档没有、但产品必须有的时刻）

### 时刻 1 · 安装（目标 < 1 分钟）
- **用户做的**：双击。然后什么都不做。
- **他看到的唯一一句话**：
  "你的电脑已加入网络。空闲时它会替你接活，收益记在你自己电脑上。"
- **验收**：这一屏**不允许出现任何需要用户回答的问题**——没有注册、没有手机号、
  没有偏好、没有"是否允许"。
- **情绪目标**：像插上电源，不像签合同。
- **最容易失败的地方**：装完之后没有任何"它在正常工作"的信号，
  用户以为装坏了，卸载。所以紧接着必须是**"状态"**，而不是"开始使用"。

### 时刻 2 · 第一次"被发现"（几秒内）
- **他看到的**：有别人。三个邻居，其中一个刚完成一单。
- **情绪目标**：原来不只我一个。
- **验收**：这一屏出现的必须是**人的痕迹**，不是网络结构。
- **最容易失败的地方**：给出星图或节点清单 → 用户以为要配置网络 → 退出。

### 时刻 3 · 第一笔收入
- **只显示三样**：干了什么、挣了多少、凭证可查。
- **验收（产品的诚信底线）**：金额旁边必须紧跟"对方已签收"。
  **没有签收的钱，不许显示为收入**；宁可显示"待对方确认"。
  把"我以为赚了"和"对方认了"混为一谈，整个产品的可信度当场归零。
- **情绪目标**："我的电脑刚才真的自己完成了一笔，对方签收了。"

### 时刻 4 · 第一次"下单"
- **用户做的**：说一句话。结果回来。
- **验收**：从"一句话"到"结果"之间，用户**不做任何选择**——
  不选摊主、不选价格、不选方式。
- **情绪目标**：叫车不需要认识司机。
- **必须补的一个例外**：结果不好时，用户要有**"这单我不认"**的动作，
  而这个动作本身是产品的核心能力之一（它会产生一份"我不认"的凭证）。
  **"没有仲裁员"不等于"用户没处说话"**——前者是对第三方的拒绝，后者是对用户的失职。
- **最容易失败的地方**：让用户"挑一个 agent"（把决策成本推回去），
  或者价格不透明（结果回来了才告诉你要付多少）。

### 时刻 5 · 第一次"对账"（**整个产品最重要的一次情绪交付**）
- **用户做的**：点开账本，点一下"验证我的账"。
- **验收**：验证结果必须能落到**具体一笔**——点进去能看见凭证本身，
  而不是只给一个绿勾。
- **情绪目标**：**从此我不需要相信任何人。**
- **最容易失败的地方**：绿勾是装饰。用户点一次没看懂，就再也不会点第二次——
  产品最核心的差异化随之失效。

### 时刻 6 · 第一次"摆摊"
- **用户做的**：回答两个问题——**你卖什么、多少钱**。其余全部有默认值。
- **验收**：摆摊要**简单到能在手机上、在地铁里做完**。
- **情绪目标**："我在全球市场里有了个摊位。"
- **最容易失败的地方**：把摆摊做成技术活（配流程、调参数、写提示词）。
  它不是技术活，是摆摊——**摊主决定摆什么，但摆这个动作必须简单。**

### 时刻 0 · 装之前（原文档没有，但决定装机量）
- 下载页只有一句话，和一个**可以点开看的别人的账本样例**（脱敏、可核对）。
- **不承诺收益、不承诺规模**——承诺这两样，产品就落回"注意力生意"。

### 时刻 7 · 第 30 天（真正的稳态）
- 产品里不再有任何"第一次"。**"安静"成为体验的主语**：一个月里它没打扰过用户，
  账本自己长厚了。
- 用户打开它的动机是**"我想看看我的账"**，不是产品把他叫回来。
- **这是这套产品的稳态，也是它区别于所有注意力产品的唯一证据。**
  第 30 天的体验不好，前六个时刻做得再漂亮也没用。

### 时刻 8 · 唯一必须打扰的时刻
- **凭证对不上，或密钥没有备份。**
- 产品必须说话，且必须说得让不懂技术的人听懂。
- **沉默是一种资产，要花在刀刃上**：正因为平常不说话，这一次才有分量。

## 3.2 一句话总结体验

**用户感知到的永远是"我的一句话得到了结果"，以及"这本账是我自己的"。
中间的全世界——别人的电脑、它们在哪、怎么找到的——都不该被感知到。**

# 第四部分：反面清单（强化版）

# 第五部分：这套定义怎么算成立（整体验收）

不看功能清单，只看五个可观察的行为：

1. **装完 3 分钟内**，用户能不读任何说明地说出"我的电脑现在在干什么"。
2. **只有两台电脑时**，两个人能互相干活、互相验证，且谁都不需要相信第三个人。
3. **任何一个"赚了多少"**，都能点进去看到对方的签收。
4. **第 30 天**，用户打开它的动机是"看我的账"，而不是产品把他叫回来。
5. **外部一切都消失后**，用户手里的账本依然完整、依然算数。

五条全过，这个产品就是它说的那个东西；有一条不过，那条就是它真实的样子。

# 第六部分：需要你拍板的四个未决问题

作为产品定义，这四件事不定，后面每个细节都会摇摆：

1. **"赚钱"的第一层含义是现金、债权，还是两者分阶段？**（见 1.7）
   定不了这个，"你的电脑在赚钱"这句话就不能写进产品。
2. **坏交付的代价谁承担？** 没有第三方裁决时，最轻的答案可能是：
   不签收 = 不付 + 账本上留一条"未签收"的记录 + 允许重做一次。
   但这个"一次"要不要有上限、由谁计数，必须定义。
3. **密钥丢了怎么办（面向不懂技术的用户）？**
   产品层的答案不是"找回账号"，而是**"身份是一张你可以抄在纸上、锁进抽屉里的纸"**。
   要不要为这张纸设计一个"给它一张纸"的体验，需要拍板。
4. **账本给别人看到多少？** 默认应当是：**只出示那一笔的凭证，不出示整本账。**
   这决定"摊位"页上能展示什么信用信息。
