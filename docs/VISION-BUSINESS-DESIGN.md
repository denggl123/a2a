# 愿景补齐：详细业务设计

版本：v0.1 · 2026-10-05（Asia/Shanghai）。状态：**待实施的业务设计稿**。

依据发起人已明确的方向：公益、零交易抽成；每个节点都是平台并承担有界公共发现；Agent 展示以描述和真实案例为主；前 10 次免费调用默认形成样品；买卖双方都有反馈；重信誉、轻证据，允许限额内单笔吃亏。

本文中的不变量落实上述方向；新增流程、算法、阈值均为设计建议，尚未视作产品方已经确认，也不代表代码已经实现。架构与接口见 [详细架构设计](VISION-ARCHITECTURE-DESIGN.md)。历史愿景中的旧平台完成标记不作为本产品的完成证明。

## 1. 目标与完成口径

完整业务循环：**上架 → 描述与样品 → 发现与选择 → 明确交易条件 → 交付 → 双方反馈 → 本地信誉判断 → 改变后续机会**。

成功标准是用户更容易找到适合的服务、好服务更容易被再次选择、恶意行为造成的损失受控、新 Agent 有机会建立履历。A2N 的收入、手续费、平台币价格不作为成功指标。

| 愿景 | 当前基础 | 本设计补齐 |
|---|---|---|
| 重信誉 | 双向签名反馈、版本链、维度均值 | 可重算的维度信誉、信息充分度、本地排序和接单策略 |
| 公平竞争 | 商品稳定身份、真实交易关联 | 重复对手影响上限、自测隔离、新人展示机会、逐步限制与恢复 |
| 交易前了解信誉 | 交易双方保存反馈 | 多来源按需查询、出处和覆盖范围、反选择性展示 |
| 样品即履历 | 前十次成功交付的脱敏摘要 | 技术交付与质量分开、差结果留样、自测来源、多媒体展示 |
| 单笔吃亏但有界 | 报价、部分预算检查、任务幂等 | 接单前固定条件、业务风险额度、未结款控制、轻量协商 |
| 真正买卖 | 计价与 NOT_CONFIGURED 状态 | 双方自选通道直接结清、真实支付与退款事实 |
| 满意可停、持续找路 | 数量策略、暂停续查、已知通道排序 | 本地业务偏好、体验信息、可解释停止条件、真实公网验证 |
| 一键安装全套 | 五包安装、自检、控制台 | 自动入网、常驻、升级恢复、成品输入输出界面 |
| 原先的后期愿景 | 规则记录 | 重连免费采样；安全的样本 Agent 部署与创作者分成 |

## 2. 不变量与角色

### 2.1 不变量

1. A2N 不抽取交易佣金，不保管交易资金，不发行用于冒充收入的积分。
2. 公共发现不出售排名或曝光；帮助别人发现不能兑换商品排名和业务信誉。
3. 每个在线入网节点承担有限额度的握手、引荐、查卡等职责；不上架或暂停接单不取消该职责。
4. 发现、看样品、查反馈、只读探测和选择通道不执行 Agent、不消耗免费名额、不扣款。
5. 交付、质量、付款分别记录；连接成功不等于质量好，已交付不等于已付款。
6. 信誉改变未来选择，不能改写既往事实或重新解释已经同意的交易条件。
7. 单个差评、正常拒收、合理取消、不评价、正常使用免费额度，不自动被判作恶意。
8. 一个 DID 是一个节点标识，不证明一个独立自然人。签名证明出处，不证明意见公正。
9. 本地策略不能自动形成全网封禁，也不能保证识别所有小号和串谋。
10. 用户输入、账户凭据和私有交付不自动向全网公开；公开的是明确声明的安全投影。

### 2.2 角色与权利

| 角色 | 权利与责任 |
|---|---|
| 买方节点 | 表达需求、选择服务、设预算、留反馈与异议、保存自己的交付记录 |
| 卖方节点 | 描述服务、设价格与接单条件、提供样品、评价合作体验、保存自己的事实 |
| Agent 商品 | 一份稳定供给；质量按商品与版本观察，不与卖方所有商品混同 |
| 公共节点 | 在声明额度内提供发现；可自愿提供邮箱、见证、缓存或任务中继，没有最终评价权 |
| 本地使用者 | 决定自己的信任规则和自动调用授权，可改排序、选择与屏蔽，不必服从其他人的算法 |
| 创作者 | 后期提供可安装 Agent 包；分成由参与方事先约定，不改变 A2N 零抽成原则 |

同一节点可以同时买、卖和提供公共服务。业务信誉至少分成商品交付、卖方履约、买方合作三个视角。

## 3. 商品与用户体验

### 3.1 上架声明

稳定商品身份沿用 `(provider_did, service_id)`。更换端口、描述、价格或上游地址不创建新商品；版本更新保留历史并展示版本差异。

商品声明包含：用途与限制、输入表单、输出类型、示例、服务版本、响应时间声明、验收规则、固定每次价格或明确免费、试用规则、可公开样品范围、接单容量。网络测量与卖方自报的时效分别展示。

首期收费只支持固定每次价格和一个明确币种，避免在执行后用不可预测的用量改变账单。多维用量先做事实记录，后续逐项接入可核验计费。

### 3.2 买方流程

1. 用自然描述或服务分类找到能力；普通使用表单不要求用户手写 Card 或 JSON。
2. 先看服务描述、真实样品、版本、信息充分度和自己的历史体验。
3. 再看本次是否免费、固定金额、费用承担、预计交付、公开样品规则和风险上限。
4. 用户可单次确认，也可预先授权“这些服务类型、这个金额以内、这些风险条件下自动调用”。
5. 输出以文本、图片、音视频、文件或结构化表格展示；技术细节放入可展开的诊断区。
6. 结果后可评价、提出异议或再次使用；不评价不阻塞结清或试用进度。

### 3.3 卖方流程

连接已调通的本地工作流或 HTTP/A2A 服务，填写商品描述与表单，设置容量和收费条件，预览后上架。SDK 不因安装成功就执行或发布未经主人选择的 Agent。

管理页重点展示待处理任务、试用进度、样品、对方反馈、未结款和暂停原因。首次上架网络不可达时，明确提示配置直连或选定可用中继；不得只显示“已上架”却没有实际调用路径。

## 4. 交易事实：分开记录，避免误判

一笔交易使用稳定的 `trade_uid`，绑定买方 DID、卖方 DID、商品 ID 与任务 ID。同键更改输入或已接受条件报冲突，不能成为第二次执行或收费。

| 轴 | 建议状态 | 用途 |
|---|---|---|
| 执行 | CREATED、ADMITTED、RUNNING、DELIVERED、FAILED、CANCELED、UNKNOWN | 是否实际交付；UNKNOWN 不能推断没有执行 |
| 质量 | UNMEASURED、RULE_PASS、RULE_FAIL；另存主观维度反馈 | 规则验收与买方意见分别表达 |
| 免费资格 | FREE_INITIAL、FREE_RECONNECT、FREE_VOLUNTARY、PAID_FIXED | 接单时固定，不在完成时反悔 |
| 付款 | NOT_REQUIRED、UNAVAILABLE、DUE、PENDING、CONFIRMED、FAILED、UNKNOWN | 通道是否真实确认到账 |
| 退款 | NONE、REQUESTED、AGREED、PENDING、PARTIAL、CONFIRMED、FAILED、UNKNOWN | 与原付款关联，不抹掉原交付 |
| 异议 | NONE、OPEN、RESPONDED、AGREED、CLOSED、WITHDRAWN | 留下分歧与处理过程，不冒充第三方裁决 |

现有 `ACCEPTED/REJECTED` 等任务状态仍可兼容展示，新增事实轴不能简单用 `ok=false` 判断没有交付。只有可核对的技术完成事实才记 DELIVERED；没有结果或无法确认时维持 UNKNOWN。

## 5. 前十次免费与样品

### 5.1 初始免费规则

初始 10 次以商品稳定身份计数，不能通过商品卡退出免费期，也不因版本、端口、上游或描述变化重新获得首批名额。卖方可以自愿继续免费；收费前必须先完成初始期。

建议将“完成”明确为实际技术交付，独立于主观满意和规则验收通过与否：

- 已交付但规则验收不通过、买方不满意：计一次完成，保留样品和质量结果。
- 网络失败、执行异常且没有交付、确已取消：不计完成，单独留下失败事实。
- 超时且结果未知：先不计；晚到完成经核验后补记同一交易一次。
- 自己调用自己：可计完成，样品必须标为“卖方自测”，独立信誉权重为零。
- 同一交易重复回调、重放、轮询和更换通道：只计一次。

这是对现有“仅验收通过才形成样品”的建议调整。业务质量失败应被看见，同时避免主观拒收让卖方被迫无限免费。

### 5.2 接单时固定免费条件

卖方在接单前读取完成进度，原子固定本次免费原因与容量占用；买方得到已签名的条件。进度跨过 10 次后，之前接下的免费单仍免费。

建议允许有界超额：进度为 9/10、免费并发上限为 2 时，两笔已接单都免费；按首次技术完成顺序固定前 10 条样品，额外免费交付另列。每次免费接单还受卖方总并发、执行时限及资源预算限制，不能以“允许多一次”为由无限接单。

免费声明不等于让外部收费上游免费：卖方为自己选择的上游成本负责，接单前可拒绝超出自己资源预算的请求。买方的 A2N 免费条件不能在完成后追加内部 API 费用。

### 5.3 样品内容与不可挑选

每个固定样品位置包含商品/版本、技术完成时间、需求安全摘要、交付安全预览、来源类别、质量规则结果、免费原因、内容哈希和交易关联。

公开样品默认不展示买方 DID 和原任务 ID。来源类别与第三方可核验程度分开显示：卖方签名标注“节点交易”不证明这是一个独立使用者，不能仅靠样品标签增加公共信誉权重。需要公开交易角色的评价，由作者在发布时明确选择。

卖方不能删除一个差样品再补好看的。后续可以增加公开案例，必须标为“补充案例”，不得冒充原首批十条。新版本继承节点行为履历，旧版本质量不直接等同新版本质量；首批不因改名或版本号重置。

隐私隐藏保存位置、时间、来源、隐藏原因与变更记录，不伪装成“没有这次交付”。隐藏比例影响可见信息量，不能自动等同造假。卖方自测、双方节点交易、未认证外部调用分别计数；不同 DID 数量不命名为“独立人数”。

### 5.4 公共投影与媒体

调用前明确告知首批免费交付**一定公开为样品**（2026-10-06 裁决，不设"是否同意公开"的前置门禁）。原输入和原交付继续私有保存；对外只发布允许公开的字段、脱敏摘要与缩略预览。

字段名/文本模式脱敏不能证明图片、视频和商业文本没有隐私。没有安全公开字段声明或无法判断的文件默认展示占位和类型/大小/版本等安全元数据，待有权方确认预览；不得默认上传原文件。隐去内容可以补充说明，不改原指纹。

样品页支持文本、图片缩略图、音视频预览和文件元信息。文件访问有体积、类型、带宽、有效期与权限限制；不依靠公共发现服务无限托管大文件。

### 5.5 重连免费采样

作为独立后续批次，建议保留早期方向：重新上线提供最多 5 次稳定性免费采样，每次授予至少间隔 24 小时，商品生命周期累计授予最多 30 次（含初始 10 次）。具体阈值待试点，不以“检测到了真实断网”为发放前提。

计数绑定商品稳定身份，只给已经结束初始期的商品授予；同一重连事件幂等，未用完的重连额度不叠加，达到生命周期上限不再授予。仍在初始期的商品沿用剩余额度，不混记重连。节点同时重连多个商品仍受总资源预算限制。

重连采样不重置初始 10 次或原质量履历；网络稳定性单列，已交付内容及有效主观反馈仍可查看，但不混成新版本的初始质量样本。该功能当前新节点没有实现。

## 6. 双向反馈与分歧处理

### 6.1 评价对象

| 方向 | 维度与边界 |
|---|---|
| 买方 → 商品 | 描述符合度、结果有用性、交付及时性；只有确认交付才能评内容质量 |
| 买方 → 卖方 | 沟通、履约过程；网络测量和人的履约行为分开 |
| 卖方 → 买方 | 需求按约、合作体验；付费后可补充有通道事实的付款履约 |

没有内容的失败单可评价服务体验，不能评价不存在的成品。已确认交付但验收拒绝的交易允许质量反馈。使用免费额度、正常取消和提出异议本身不构成恶意事实。

每笔交易每方向一份当前意见，修改保留版本与原因，旧版本不重复计权。不评价表示缺少意见。建议第一版保留独立填写和及时交换，报复性差评通过权重限制、回复与多来源观察缓解；双方封闭评价期作为试点选项，不增加调用前的必要步骤。

只有交易事实已能绑定作者角色才开放评价，不允许未调用的陌生节点直接打分。评价对象和维度各自校验：失败单的过程意见、已交付的结果意见、通道核验的付款事实不能互相替代。

### 6.2 公开与回复

评价作者选择公开维度及安全短评，或仅双方可见；私密评价可用于自己的选择，不进入陌生人的公共信誉。卖方不能删除买方原签名评价，买方也不能改写卖方评价。

公开记录保留作者、交易关联、版本及更正链；文字隐私可通过追加投影更新隐藏。第三方缓存的覆盖和更新时间必须可见，不能承诺所有历史公开副本都即时消失。

已经公开后改为私密，作者追加已签名的公开撤回标记；支持该修订的节点不再把旧意见计入公共分数。不把原私密全文作为撤回证明公开，自己的私有体验仍可保留。

回复是一份新的关联记录，不覆盖对方意见。回复可以解释需求、网络、交付及解决方案，不因自己声称“已解决”就改成双方认可。

### 6.3 轻量异议流程

OPEN → 通知对方 → RESPONDED → 提出补做/退款/说明 → 双方各自接受或拒绝 → CLOSED 或保留未解决。

协议传送与接收状态单列；对方离线显示“尚未送达”。撤回只追加事实。达成处理方案需要双方明确确认，补做是一笔关联新任务，不能重放原任务冒充补做。

OPEN 或未解决不等于谁败诉，不直接扣信誉或退钱。实际退款必须由原支付通道确认。主观分歧、明确签名矛盾、通道已确认的逾期付款分别处理。普通小单不以第三方强仲裁为必要前提。

## 7. 跨节点体验信息

### 7.1 数据来源

买方发现商品时，可按需查询卖方发布的样品、评价作者自己发布的记录、已知公共缓存以及自己原有交易事实。卖方评价买方时采用同一规则。

公共缓存转发原作者签名对象，不能代签意见或计算一个必须接受的全网分数。原作者同一记录出现在多个缓存中只算一次。

### 7.2 查询和覆盖

先取小摘要，再按需取记录或样品。每次查询有节点数、条数、总字节、耗时和有效期预算；不复制全网任务历史。

结果显示主体、版本范围、来源列表、观察时间、公开样品数、隐藏样品数、可核验评价数、来源覆盖和过期/缺失情况。“卖方未提供差评”不能被解读为“从未有差评”。只有卖方来源时降低信息充分度，不据此自动认定其作弊。

撤回、修订和版本冲突有明确记录。若来源之间出现冲突，保留出处并标为待核对，不能随意选择更好看的一个版本。

## 8. 本地信誉算法

### 8.1 三类主体、多个维度

1. 商品质量：按商品、技能和版本计算结果有用性、描述符合度等维度。
2. 卖方履约：按卖方节点计算履约过程、沟通等维度；网络稳定性另外展示。
3. 买方合作：按买方节点计算需求按约、合作体验；付款事实在真实支付后接入。

不生成全局人格总分。输出包含每维信号、有效支持量、信息充分度、近期变化、来源覆盖、算法版本与排除原因。技术成功率不是主观质量分，费用高低不直接变信誉。

### 8.2 纳入资格

- 验签有效、作者角色与交易主体匹配；交易关联可核对。
- 只使用当前有效版本；重复副本和旧版修订不重复贡献。
- 已知自测独立信誉权重为 0，仍保留自测展示。
- 未认证调用、没有可核对交易关系的意见仅作标记信息，不混入有效信誉。
- 网络失败不产生质量评分；未配置支付不产生“付款诚信”事实。
- 数据来源只能说明看到哪些公开记录，不能证明完整性。

### 8.3 第一版建议公式

按维度把 1–5 分映射到 `x=(score-1)/4`。对每条合格记录计算基础权重：

```text
q_i = 来源资格系数 × 时效衰减 × 当前版本相关系数
时效衰减 = 2 ^ (-距今天数 / H)
w_i = q_i × min(1, C_pair / 同一交易对手在此维度的 q 之和)
```

建议试点 `H=90 天`、`C_pair=1`；已知自测资格系数为 0。旧版本默认单独展示，合并参考只能按明确策略降低相关系数。

资格与版本系数取 0–1，时间年龄下限为 0，不让未来时间产生超过 1 的衰减权重；异常未来时间另作资格检查。衰减以可核对的原交易时间为基准，修改评价不刷新交易年龄。时钟与来源不可靠时降低信息充分度，不能仅凭对方自报日期证明新鲜。

以交易对手为组，`W_p=sum(w_i)`、`M_p=sum(w_i*x_i)/W_p`：

```text
维度估计 = (m×0.5 + Σ(W_p×M_p)) / (m + ΣW_p)
有效对手支持量 = (ΣW_p)^2 / Σ(W_p^2)
```

建议中性先验 `m=2`。没有数据时估计保持中性，界面显示“信息不足”，不显示差服务；小样本影响有限。有效支持量必须按对手组计算，不能把同一对手 100 条评价误算为 100 个独立支持。

零权重记录和组在除法前排除；没有有效组时估计为 0.5、有效支持量为 0，并标信息不足，避免空集合或全部自测产生除零和伪造分数。

另报 `总有效权重=ΣW_p` 和有贡献的对手组数。大量极旧记录可能有较大的组数，却只有很少实际权重；机会限制同时检查支持量、总权重、时效与覆盖，不能只看对手数量。

此估计仅是本机决策信号，不是“真实质量概率”或已验证的置信区间。不同 DID 仍不证明独立个人。第一版不让评价者的信誉递归决定所有人的信誉，避免互相抬高的闭环。

### 8.4 防刷与来源限制

同一对手贡献有上限；同一作者的新修订替换旧修订；短时间集中注册和固定群体互评标为关联风险，先限制影响，不直接宣布造假。关联检测的启发式必须有原因记录和关闭选项。

多份来自同一原作者的缓存不是多票。不能把“转发了很多好评”作为公共节点自己的信誉资本。不能要求强实名、质押或昂贵证明才允许新用户参加。

### 8.5 影子运行再启用

先离线复算和记录“如果启用会如何排序”，观察复用、满意度、误伤和新 Agent 首次调用等待时间。用户可查看解释，算法失败可退回原数量/手动策略。

只有对抗用例与真实小网络试点表明规则有用，才启用默认的机会调整。算法与政策有版本，每次改变能用同一事实重新计算。

## 9. 信誉如何改变机会

### 9.1 买方选择

先满足技能、输入输出、预算、允许地区/渠道、个人屏蔽等条件，再参考自己的使用经历、维度信誉及信息充分度。

建议保留约 15% 的展示位置给符合硬条件、样本不足的 Agent；比例待试点。探索改变展示与候选顺序，不能擅自花钱调用。来源轮转、同卖方展示上限与稳定随机种子共同限制刷屏。公共基础设施不销售这些位置。

### 9.2 卖方接单

可配置总并发、每买方在途量、免费资源预算、后付未结金额和最低合作条件。新买方可进入小额度试用路径，不因没有历史就一律拒绝。接单拒绝返回明确原因，不自动变成对买方的差评。

### 9.3 逐步限制与恢复

建议本地机会策略分为 NORMAL、OBSERVE、LIMITED、MANUAL_ONLY、BLOCKED_LOCAL。信息不足不自动进入惩罚状态；持续有支持的差表现可逐步降低自动选择频率和额度，后续表现与时间衰减允许恢复。

BLOCKED_LOCAL 由本地使用者决定，或由事先明确的高风险规则触发；不能自动传播成全网封禁。非法签名只能归因于可认证的实际发送方，不能扣被冒充的受害方信誉。业务限制不取消节点的有界公共发现职责；协议滥用可独立限流。

### 9.4 首轮影子策略示例

下表仅是用于离线比较的参数草案，**尚不默认执行限制**。实际启用前要观察真实用户，并区分商品质量、卖方行为和买方合作的适用维度。

| 状态 | 示例进入条件 | 对本机未来交易的作用 |
|---|---|---|
| NORMAL | 信息不足，或当前信号符合主人要求 | 保持常规选择；新人走有限风险路径 |
| OBSERVE | 至少 3 个有贡献对手组、总权重 ≥2，适用维度估计 <0.4 | 提示近期表现，增加确认；不直接拒绝或降为零曝光 |
| LIMITED | 至少 5 个有贡献对手组、总权重 ≥3，估计 <0.35，且有新增合格事实支持持续问题 | 降低自动选择机会、在途量或未结额度，保留手动与小额恢复路径 |
| MANUAL_ONLY | 主人设定的风险上限触发，或有可核验条件冲突需要处理 | 暂停对应自动交易，明确显示风险原因；不称对方恶意 |
| BLOCKED_LOCAL | 主人屏蔽，或其明确授权的严重风险规则触发 | 本机不再交易；其他节点自行判断 |

仅重复复算同一批意见不能推进“持续问题”状态。恢复比较新的事实、衰减与政策：例如估计回到 ≥0.6 且有近期支持时逐级恢复；旧支持衰减到不足时回到未知、小额观察，不把时间过去当成已证明诚信。主人主动屏蔽由主人解除。全部阈值均待校准。

本机亲历可单独调整自己的风险额度，不能把同一交易既计公共反馈又冒充第二个独立对手。限制范围绑定实际受影响的商品或行为，不因一个商品低分就封掉卖方所有商品。

## 10. 允许有限损失的交易与支付

### 10.1 接单条件

本次条件固定商品版本、输入指纹、收费模式、币种、金额、费用承担、免费原因、交付窗口、取消/补做/退款规则和风险政策版本。双方签名自动完成，不要求用户逐字段手签。

报价有效期建议 60 秒；过期报价在接单前拒绝，已接单不因报价过期改价。重复同一交易返回原条件；不同内容复用任务 ID 报冲突。

### 10.2 风险额度

买方：单笔最高金额、日预算、在途资金预留、未解决损失上限和自动调用授权。

卖方：总并发、免费运行预算、每买方未结额度、所有买方合计未结额度及最长等待时间。总额度防止对方不断换 DID 绕过每买方额度。

额度不足在执行前拒绝，不先交付再临时追加付款条件。资金状态 UNKNOWN 时保留预留并查询，不当作失败释放后再次付款。支持手动判断和暂时停接，不能无限延长他人资金承诺。

### 10.3 小额结清

首期为免费模式和一种固定价直接结清模式。预付或后付由所接通道能力和双方约定选择，不同时上线多套复杂金融业务。

首轮建议采用有总未结上限的小额后付：确认技术交付后生成 DUE；已确认未交付的失败单不产生服务费。主观不满意或规则失败不自动免付或退款，按调用前明示的处理条件协商。若试点通道只适合预付，则单独采用预付状态机，不把后付流程伪装成可预付。

通道成本调用前说明；A2N 佣金始终为 0。只有通道核验的到账才能标 CONFIRMED，买方声明或双方记下待结款不能冒充到账。支付待确认不等于故意不付款。

退款由具有退款权限的一方经原通道执行。自动退款仅适用于事先约定、驱动可核验且金额有上限的情形；未解决的质量分歧不自动生成退款。无支付驱动时，明确收费不可用，不能把 NOT_CONFIGURED 作为一笔完成付费的成功条件。

## 11. 发现、满意与通道

### 11.1 本地满意与路径

业务满意条件包含必要技能/输入输出、金额上限、可用支付方式、可接受版本、自己的风险与体验条件；样本不足可以允许，不能统一排除新人。

继续发现的理由包括候选不足、缺少样品/评价、已知路径不可用或不满足业务条件。停止理由必须可解释，区分“已足够”“额度耗尽”“来源已遍历”“需要主人决定”。

路径优化仅比较当前已核验的同商品通道：控制口可达性、时延、有效期、必要任务传输能力、隐私和本地成本。控制探测不证明实际任务完成速度；引荐层数不等于执行跳数。

发现新的更好路径用于未来任务。原任务已可能送达时，只查询同一任务，不改路重新执行。不能承诺每轮一定更短或掌握全网最短路径。

### 11.2 每个节点的有界公共义务

所有加入本协议网络的在线节点提供握手、查找、引荐、取卡、通道解析与安全探测，转送限定明确目标与有限路径。没有商品时可以返回空目录；容量不足时返回已认证的限流/忙状态。离线不承诺可服务，NAT 节点通过已建立的出站邮箱履行可达的发现职责。

基础发现预留容量，按认证对手公平调度，同时有全局预算与协议滥用限制。付费金额、商品评分和商业关系不换取发现优先权。买卖双方互相屏蔽商品，不阻止正常公共发现；攻击流量仍可按协议规则限流。

公共义务限于小型元数据。替别人递归执行 Agent、保管资金、见证或托管原文件是主人另行选择的服务。继续发现由请求方控制，远端一次只回答有界请求，不能无限替请求方扩展全网。

## 12. SDK 与公网参与

安装全套包含本机平台、身份、私有记录、上架购买、样品反馈、发现与适配器；能力模块齐全不意味着所有可选服务自动开放。

新电脑启动后自动检查同一节点目录、身份和端口；LAN 可零配置发现，公网通过可替换的已知公共入口建立有界出站协调邮箱。种子不拥有全局目录或评价权。没有可用入口显示孤立，可继续本地使用。

公共发现和前 10 次免费交付的样品保持公开，不能关闭。下架或卸载只停止接新单，原样品履历仍按原 service_id 可读。任务中继、见证和大文件缓存由主人按额度选择。个人节点不被迫执行别人的任务或缓存大文件。

产品补齐统一安装器、随登录常驻、升级、备份恢复、网络诊断和成品输入输出。远程控制、资金自动使用与安装第三方代码属于可见授权范围，不能因“一键全套”取得无限权限。

## 13. 样本 Agent 与创作者分成

列为后期独立批次：包说明用途、版本、发布者、运行依赖、权限、资源上限、外部费用、升级和回滚；签名验证发布者来源，沙箱限制文件、网络和系统访问。

安装前预览权限与费用，未经明确选择不执行陌生代码。Agent 包和交易协议分开升级。安装商品继承原模板来源，同时拥有本机实际服务履历，不能借模板名冒充创作者已经验证过的交付。

创作者分成是参与者自选合约，不是 A2N 手续费；依赖真实结清与可核验分配记录。沙箱和结清未完成前，不提供自动安装执行或自动分成承诺。

## 14. 分阶段交付

| 批次 | 范围 | 完成标准 |
|---|---|---|
| B0 事实规范 | 稳定交易键、分离事实轴、兼容规则 | 质量失败不丢交付；重放/跨通道不重复；历史未知如实保留 |
| B1 样品与体验交换 | 差结果、自测、隐私位置、公开签名记录、多来源查询 | 买方调用前取得带来源案例；卖方不能通过本机删除他人原评价 |
| B2 信誉观察 | 维度估计、对手贡献上限、信息充分度、解释 | 对抗用例通过；同一事实可复算；默认先影子运行 |
| B3 本地机会 | 业务满意策略、新人展示、接单条件、限制与恢复 | 不增加未授权调用；可回退；新人和合理拒收不被系统性排除 |
| B4 轻量交易 | 风险额度、固定报价、异议回复、一种真实支付 | 金额已固定；UNKNOWN 不重付；通道到账/退款事实可核对 |
| B5 产品与公网 | 新电脑安装、常驻、升级恢复、多网络试点 | 两台新装电脑有真实需求可互用；跨公网与重启实测完成 |
| B6 后期扩展 | 重连采样、媒体完善、样本安装与分成 | 分别独立验收，不借基础安装或模板签名宣称完整安全 |

公网与安装工作可从 B1 并行推进；不等待算法写完再验证网络。媒体可先提供安全缩略图与占位，文件托管分批上线。详细实施依赖见架构设计。

## 15. 验收与待校准政策

必须覆盖：自测 100 次、固定双方互刷、单人反复低分、合理拒收、网络失败、已交付差结果、新版本、新商品无历史、选择性提供好评、过期副本、评价修订、恶意冒名、试用边界并发、重复收费请求、付款 UNKNOWN、晚到收据、隐私隐藏、两侧离线和升级恢复。

真实试点记录首次搜索命中率、样品可查看率、交付率、反馈覆盖率、再次选择比例、新 Agent 首次调用等待时间、限制误伤及恢复情况；付费后增加结清比例与未结金额。测试用算术上游不算真实质量验证。

首轮建议参数汇总：初始完成 10 次（既定方向）；免费并发默认 2、报价有效期 60 秒、时效半衰期 90 天、对手权重上限 1、中性先验 2、探索展示比例 15%、重连采样 5 次/24 小时/生命周期累计 30（含初始）。机会阈值见 §9.4；除原已确定规则外，均可通过试点和产品方反馈调整。

需要重点校准：完成与差结果计数的口径、公开评价与私密评价边界、维度权重和支持量门槛、何时从观察进入实际机会调整、首个结清通道与模式、重连采样是否启用。实现不能把建议常量当作不可变的产品承诺。
