# 当前项目状态与开发主线

更新：2026-10-11；版本：0.2.0b6，Beta。本文是当前状态入口，历史设计和验收记录保留原日期。当前巡检证据生成于 `artifacts/project-health.json`，每次开发的测试与部署结果独立记录。

## 1. 产品定位与价值

A2N 是零平台抽成的对等 Agent 供需网络。每个完整节点拥有供给、需求、发现、交易和本机治理能力，并承担有额度限制的公共发现义务。

它的价值是让个人的小工具和已有 Agent 成为可发现、可体验、可交换的服务：样品降低尝试成本，双方信誉降低判断成本，积分提供自愿互惠，公开协议减少对单一中心目录的依赖。评价与有限争议处理支持持续淘汰失信服务，不承诺每一笔交易绝对公平。

技术上的业务闭环已经形成。社会价值仍需要真实供需、持续服务和独立用户反馈验证；受控工程调用证明功能可用，不能证明已经形成可信繁荣的市场。

## 2. 唯一业务主线

```text
公共逐级发现 → 本机候选合并 → 私人条件筛选 → 个人排序
→ 明确选用、导入投影 → 固定任务/报价
→ 前十次样品跳过一切结算；其后按双方条件匹配结算
→ 原任务交付 → 模板验收、任务质量评审
→ 双方反馈、有限争议 → 本机信誉/选用效果更新
```

供应方配置支持方式，使用方配置方式顺序、金额和费用上限及自动授权。支付协调层固定原计划，调用独立的原生币、x402 或积分模块。原生币先付款再调用；积分按服务交付规则处理；x402 依照该模块的授权和收据流程。不同方式不能被解释成同一种到账语义。

前十次实际免费技术交付必定公开为脱敏样品，跳过所有资金和积分结算。查询、发现、重放、交付失败不制造新样品。交付成功、质量评价、资金确认、退款和争议分别记录。网络故障造成的未知结果只恢复原任务/原单，不切换支付方式、另付一笔或重新执行 Agent。

旧中央平台和旧财务/信誉包已退役；少量旧 URL 是当前同一业务服务的兼容入口。不存在第二套正在维护的交易账本。

## 3. 六层职责与包边界

| 层 | 当前职责和主要模块 | 边界 |
|---|---|---|
| 基础 | 身份与签名、规范序列化、加密存储、脱敏、整数计价 | 不决定样品、信誉或支付资格 |
| 网络 | HTTP/A2A 传输、P2P 观测、直连、任务/文件中继 | 返回连接和传输事实，不做个人排名 |
| 协调 | `coordination` 搜索/引荐/会话/额度/通道；`payment_coordination` 条件协商/固定计划/恢复 | 发现不执行 Agent；支付由业务触发，调用独立子模块 |
| 业务 | `TradeService`、`AutomaticTrade`、`calls`、样品、反馈、争议、信誉策略；`selection`、`task_quality`、`calibration`、私有学习；工作流和成果资产 | 免费资格在这里决定；评估通过事实端口读取数据，不读取钱包账本决定排名 |
| 接口 | 本机受保护 API、公共签名协议、`NodeClient`、控制台、A2A/JSON/MCP 适配 | 适配协议，沿用同一业务链 |
| 产品装配 | `Daemon`、桌面安装/自检/常驻、备份恢复、签名升级、Docker | 注入执行/网络/支付端口，管理生命周期 |

原生币、x402 和积分是支付协调下的独立实现模块，不新增顶层业务体系。五包的依赖方向是 `kernel → p2p/acceptance → sdk → node`；这是依赖层级表达，SDK 库仍只有标准库依赖，具体实现由 node 注入。架构测试检查跨包依赖和环；同包应用服务之间仍需人工保持端口边界。

详细契约见 [架构](SDK-ARCHITECTURE.md)、[协调](COORDINATION-API.md)、[评估](SELECTION-MODULE.md)、[支付](PAYMENT-COORDINATION.md)。

## 4. 数据放在哪里

| 数据 | 归属与保留 | 对外范围 |
|---|---|---|
| 私钥、钱包/账户、请求原文、原任务入口、订单和积分账 | 所属节点加密 `runtime.db`，备份同样加密 | 不公开；支付协议只交换必要授权/签名事实 |
| 供给卡、首十次样品 | 供应方保存真实交付，公开投影、脱敏摘要和受限预览 | 公共可发现；下架不抹掉已经产生的样品 |
| 双方反馈、收据、协商与争议 | 事实原件和版本链在相关节点；公开体验需遵循发布规则 | 只使用验签、有来源的事实；争议不等于裁定欺诈 |
| 网络/耗时/质量/信用等多维资料 | 原始本机观测与验签缓存分开；归一化、置信度及数据年龄在评估模块计算 | 个人排序、权重、精确预算保留本机 |
| 任务质量标签、校准、私人学习 | 同意/来源/撤回/时间窗可追溯；采用建议需版本复核 | 工程和助手记录不伪装真人；不改他人的公开信用或支付政策 |
| 复杂成果、工作流、备份 | 受权限、容量与保留策略管理；历史事实不能作为垃圾清理 | 私有成果须持有授权，样品不直接公开原始成果文件 |

## 5. 完成度的实际判断

| 领域 | 判断 | 尚待真实验证 |
|---|---|---|
| 单一市场闭环、强制公共样品 | 已实现并有实际跨节点调用验证 | 长期真实供需和用户体验 |
| 发现、发现后筛选、私人排序 | 会话、预算、过滤、八维评估已接入 | 真实跨公网/NAT、陌生节点规模、持续路径质量 |
| 双向信誉、争议、任务质量 | 签名反馈、版本、轻量协商、独立代码/媒体评审已实现 | 恶意多身份成本、评价分歧和真实质量标签；信誉治理默认影子运行 |
| 自动支付与积分 | 匹配、授权、固定计划、三方式、本地实际测试币、恢复和独立退款已实现 | 主网资金审计、真实支付服务商；真实多方互换规模 |
| 校准与私人学习 | 数据门槛、留出验证、同意和撤回已实现 | 合格独立真人数据仍不足；助手调用不能补成真实用户样本 |
| Agent 接入与复杂成果 | A2A、JSON HTTP、受限 MCP HTTP、签名容器工作流、流式输出/资产已实现 | 完整跨协议互通、更多第三方 Agent；容器执行/部分独立评审需要本机 Docker |
| 完整安装和发布 | 全套 Windows 程序、服务器源码包、签名/哈希/版本一致性、自检和升级已实现 | 新电脑安装体验、OS 发行证书、公开分发渠道；GitHub CI 配置存在，须看远端真实结果 |

总体定位：**可用于受控小规模试点的功能型 Beta**。本机闭环成熟度较高；公网运行、陌生参与者治理和长期数据校准的成熟度较低。单元测试数量不能换算为“整体完成百分比”。

本机当前应是 Windows 桌面节点 8771，加 Docker 三节点 18881/18882/18883；另有测试 Agent、测试链及 facilitator，它们不是市场节点。实际端口、身份和源码一致性以巡检为准。历史受控原单仍可能保持“付款确认、交付未知”，不会为了清零而重付、重跑或虚构交付；巡检会独立显示这些待核对订单。

## 7. 下一阶段顺序

1. **小规模真实试点**：有实际需求的服务、真人显式评价和撤回；追踪搜索到选用、交付、异议和重复使用，不为了校准门槛造日期或身份。
2. **公网与可靠性**：独立电脑/运营商/NAT，验证逐级发现、邮箱、路径变化、断线恢复、备份恢复和长期运行；对照未完成原单的真实证据处理。
3. **治理验证**：争议支持量、重复关系贡献上限和多身份攻击；观察误伤后再决定是否从影子模式启用机会限制。
4. **开放接入与分发**：选择真实第三方 Agent 做互通验证，执行远端 CI，在新电脑验收安装体验后公开发布；需要主网支付时再做资金安全审计。

下一阶段的主要工作是可信运行和用户验证。继续加新的支付理论、重建第二套平台、用助手数据强行启动个性化模型，都会偏离当前主线。
