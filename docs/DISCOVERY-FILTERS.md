# 发现后的筛选与展示

## 1. 层级与数据流

协调层按能力逐级发现节点、取得签名商品卡并归并通道。控制台将已经取得的候选保存在 `pool`；展示层读取商品卡生成分面，以当前条件计算 `found`，供卡片、列表和对比视图使用。

筛选不会修改原始卡片、候选集合、发现会话、邻居表或通道。不会询价、查钱包、查询积分目录、准备订单、执行 Agent 或结算。取消条件后原始候选立即恢复，不需要重新发现。

筛选只覆盖当前已取得的候选，不声称覆盖全网。筛选后数量少或为零，不代表搜索已经耗尽。用户仍可以使用协调层的“继续发现”，新候选会按同一套展示条件筛选。

## 2. 条件

| 条件 | 读取的事实 | 展示口径 |
|---|---|---|
| 关键词 | 名称、描述、能力名称与标识、技能标签、属地 | 不区分英文大小写的包含匹配 |
| 行业分类 | 已声明技能与本机分类表 | 未收录能力归为“其他” |
| 能力 | `skills[].id` | 保留原始标识 |
| 支付方式 | `accepts`、`x-a2n.accepts`、`x-a2n.payments.methods`、Agent 积分策略 | 原生币、x402、积分和其他明确声明的方式 |
| 积分服务模式 | `x-a2n.points.enabled` 与 `modes` | EARN、DEBT、PAY 分别筛选 |
| 样品阶段 | `x-a2n.trial.cap=10` 和 `ended` | 前十次免费样品阶段 / 首批十次样品已完成 / 未声明 |
| 价目声明 | `x-a2n.price_book` 的既有价格解析 | 已声明零价 / 有标价 / 未标价 |
| 能力标签 | `skills[].tags` | 按原始标签筛选 |
| 声明币种 | 价目表币种和支付声明币种 | 各币种独立；积分不换算成货币 |
| 支付网络 | 支付方法的 `network`，积分为节点积分网络 | 这是支付声明，不是发现网络或路由类型 |
| 供给方节点 | 候选 `key.provider_did`，或卡片投影/来源的节点 DID | 同一节点的供给归组；界面保留完整身份提示 |
| Agent 版本 | `version` | 精确版本匹配，不推断兼容范围 |
| 输入格式 | `defaultInputModes` 和技能 `inputModes` | 只列声明的格式 |
| 输出格式 | `defaultOutputModes` 和技能 `outputModes` | 只列声明的格式 |
| 属地 | 卡片的既有属地声明 | 缺少声明单独列出 |
| 发现验签标记 | 候选记录的 `verification=CARD_VERIFIED` | 与卡片身份自证分开 |
| 发现来源 | 控制台记录的来源 | 逐级协调发现、公共节点、点对点等 |
| 身份声明 | 卡片 `projection.attested` 或 `origin.self_attested` | 自证不等于发现验签，也不证明独立个人 |

除关键词和身份声明外，同组允许多选，满足任一项；不同组同时满足。例如“积分或原生币”与“支持欠账”一起选择时，仍要求命中欠账模式。

常用六组默认展开，其余条件放在“更多条件”。额外条件已选时保持展开。每项已选条件都有独立移除按钮；“全部”清除本组，“清除筛选”清除全部条件并保留排序和视图。

## 3. 积分与免费样品

`points_method=a2n-points/1` 只说明节点安装了积分子模块，不能据此认定某个 Agent 接受积分。

当前积分供给必须声明 `x-a2n.points.enabled=true`，且含有至少一种有效服务模式：

- **EARN**：允许免费服务，真实服务完成后供给方获得自己发行的积分。
- **DEBT**：允许使用方欠账。
- **PAY**：允许使用已有积分兑换服务。

旧商品卡明确在 `accepts` 中接受积分时仍可识别；新策略显式禁用积分则优先，不能被旧声明覆盖。只声明 EARN 或 DEBT 的供给不能被“允许用已有积分兑换”条件命中。

前十次样品是独立业务阶段，跳过一切结算。一个支持积分的 Agent 在初始阶段依然免费、不产生积分结算。筛选支持积分不等于当前调用必须结算积分。

余额、额度、发行方接受表、兑换比例和当次交易资格由询价与支付协调层决定。展示层不会代替询价判断“现在一定能成交”。不同发行方的积分不合并定价、不按数额跨发行方排名。

## 4. 数量、未知与证据

总数分为“本次到手候选”和“当前命中”。分面数字应用其他已选组，暂时忽略本组；因此用户可以看到切换本组还可能命中什么。未知字段保留为“未声明”，不会被补成免费、已验签、已完成样品或支持某种支付方式。

没有结果时保留全部条件、零命中选项和原始候选，并提供清除入口。支付及积分三种常见模式即使零命中也可查看，避免“看不到条件”被误解为产品未支持。

卡片、列表、对比和详情均显示支付与积分声明。对比视图沿用卡片上的历史证据展示；卡片没有信誉数据时照实显示暂无，不生成信誉阈值筛选或全网排行榜。后续接入公开体验与本机信誉视图时，可以增加基于已取得记录的条件，同时保持来源、版本和计算口径可见。

后续八维评分、个人偏好、质量归一化、争议信用、数据归属及刷新机制见 [个性化 Agent 选择设计](PERSONALIZED-AGENT-SELECTION.md)。该设计尚未实现；继续遵守本文“先发现、后筛选，筛选无远程操作”的边界。

## 5. 实现与核验

- `web/discovery.js`：无 I/O 的声明读取、归一与匹配。
- `web/runtime.html`：分面数量、多选、清除、排序及三种视图。
- 本机管理接口提供 `/console/discovery.js`；不扩展任何公共发现请求或支付接口。
- `scripts/runtime_logic_check.js`：声明识别、组合筛选、未知字段、零命中与无请求隔离。
- `scripts/check_discovery_filters.js`：真实已上架商品卡的浏览器交互核验，支持安装节点实际协调发现模式；不执行或支付 Agent。
