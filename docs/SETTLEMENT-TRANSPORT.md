# 私有结算协调通道

## 1. 边界

`a2n-settlement/1` 只运输支付子模块的协议消息，不做积分分录、链上签名或业务执行决定。业务仍先判断初始十次免费样品，免费业务不创建结算计划。

协调发现的六个操作保持原接口。结算、体验、协商、文件各自使用独立的协议、加密域、收件密钥、队列和预算。平台抽成仍为零。

## 2. 寻址与入网

供应卡签名覆盖 `x-a2n.settlement = {protocol, route}`。路由为明确直连源地址，或 `{kind: "settlement_mailbox", endpoint, relay_did}`。只有出站连接的节点向其选定公共节点注册短租约，中继暂存密文并由目标节点主动领取。

询价时双方签名绑定买方返回路由。接受后的计划保存原逻辑路由；继续付款、撤销、原交付恢复和退款回传使用原计划，不新建交易，也不自动切换中继。每次邮箱发送前获取目标的新租约，核验目标、中继、地址、期限和加密公钥，不把即将过期的密钥固定进计划。

首次使用入口 GET `/v1/onboarding`、POST `/v1/onboarding/connect` 属于受保护的本机管理接口。连接必须先完成签名 HELLO；失败不持久化为已连接，成功保存公共节点与出站配置。若对方声明提供密封任务中继，则接入该任务通道。配置成功与租约已建立分别显示。

## 3. 公共接口和允许的消息

全部为 POST，公共网关只开放以下明确路径，不转送本机管理 API。

| 路径 | 用途 |
|---|---|
| `/public/v1/settlement/capabilities` | 签名请求获取目标结算协议及公钥 |
| `/public/v1/settlement/dispatch` | 加密消息交付至目标子模块 |
| `/public/v1/settlement-mailbox/{capabilities,register,lookup,poll,reply,forward}` | 独立出站结算邮箱 |

密文中绑定作者、目标、请求 ID、方法、操作、消息正文和回复公钥。内外作者必须一致，子模块继续核验自己的签名、目标、原交易、有效期与授权。

| 方法 | 允许操作 |
|---|---|
| points | catalog、balance、decision、consent、prepare、apply、status |
| trades | quote、points-recover |
| payments | accept、observe、execute、recover、revoke、refund-observe |

x402 的原 `PAYMENT-SIGNATURE`、幂等标识与资源请求正文在密文内转送。HTTP 状态、付款响应头和原响应正文原样返回。链 RPC 与 facilitator 继续使用原支付通道；这个通道没有创造新的支付方式或链上多跳能力。

## 4. 加密与额度

使用 X25519、HKDF、AES-GCM；域 `a2n-private-settlement/1`，持久化独立 inbox 密钥。中继可见节点身份、时序、大小及路由，不可见业务输入、余额、授权和交付正文。

每份明文最多 90,000 字节、外封套最多 196,608 字节。邮箱最多 32 个租约，每目标 2 个、全局 8 个在途请求；每分钟 512 次转送、每作者 120 次。租约 90 秒，中继等待 18 秒，请求等待 20 秒。大文件继续通过已有加密文件模块按原交易授权读取。

直连旧入口沿用 HTTPS 或所有者明确允许的本地 HTTP 设置。加密协调通道沿用固定 DNS、签名身份和可信网络访问约束；一个引荐不能授予访问任意内网地址的权限。

## 5. 未知结果与恢复

开始发出 DISPATCH 后，超时、响应不可验签、无法确定的服务错误统一返回 UNKNOWN。不能据此换通道创建新授权或重跑 Agent。用户和后台按原计划、原授权、原交付及各方唯一决定核对。

积分通过同一守卫执行接单资格和分录，HTTP、自节点与邮箱入口保持一致。积分目录可从已验签的协调邻居导入，且先读取并验证该发行方目录；导入不修改接受比例、余额、钱包或额度。

退款沿用原双方协议和逆向独立付款。付款确认与对方收到退款通知是两个事实，通知丢失可核对原退款，不能再次产生退款转账。

## 6. 验证边界

`tests/test_settlement_transport.py` 使用无监听的供应方/买方声明地址、真实 Daemon、出站邮箱和密封 A2A，验证初始样品、积分发行与欠账、原交付恢复、目录桥接和伪造拒绝；私有 EVM 验证原生币、x402 实际交易及反向退款。测试币无现实价值。

同机模拟验证协议业务；真实多设备 NAT、运营商防火墙、长时掉线及公网性能仍需外部环境验证。
