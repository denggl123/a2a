# A2N 使用端聚合：把多个候选 agent 聚合成一条稳定调用路径

一句话：**我是使用方，我要调"财务"这类能力，但单个 agent 不稳定（挂了/超时/抽风）。
我在自己客户端里配一组候选 + 策略（轮询/按权重/失败换人/冷却退避），
谁稳用谁 —— 这是纯粹的调用端便利，与供给方无关。**

## 定位（三条划清）

1. **不注册任何卡、不接平台任务**：没有虚拟 agent、没有中间商账本、没有毛利。
   平台对这个聚合器完全无感知 —— 它就是使用方进程里的一段路由逻辑
   （client-side load balancing，成员是 agent）。
2. **每一次成功调用都是"使用方 ↔ 真实 agent"的一对一交易**：
   结算、验收、刻章、观测全走既有链路（`call_agent` 自动计时+回传观测）。
   平台账上只有真实交易，一条聚合的影子都没有。
3. **候选健康是使用端实测（本地私账）**：ok/fail/RTT 滑窗/冷却状态都在
   使用方自己手里（`docs/CALL-PARAMS.md` 口径：谁测的谁自报，报给自己）。
   平台看不到、也不需要看到 —— "我怎么调得稳"是使用方的私事。

> 与"供给方聚合"（虚拟卡转售成员、赚差价）是两种不同的形态。A2N 一期只做
> 使用端聚合：它零新增事实、账目天然一对一；转售型若未来有真实需求，另立门面。

## 机制

```
使用方进程
┌────────────────────────────────────────────┐
│ Aggregator(client, candidates=[...])       │
│   call(skill) ─▶ 策略选候选 ─▶ call_agent ─┼──▶ 真实 agent A(w5)
│                │失败？换下一个 ─▶ call_agent ┼──▶ 真实 agent B(w1)
│                └全员失败 ─▶ AggregationFailed│
└────────────────────────────────────────────┘
```

| 策略 | 行为 |
|------|------|
| `round_robin` | 轮询：游标依次起头，失败顺延 |
| `weighted` | 平滑加权轮询（SWRR）：高权重先被选、占比≈权重比，低权重也保证轮到 |
| （自定义） | `register_strategy("name", fn(candidates, state) -> [尝试顺序])` |

**failover 是所有策略共用的兜底**，不是独立策略：

- 单候选失败 → 换下一个重试（默认尝试次数 = 候选数，可配 `max_tries`）；
- 失败候选进**冷却**：时长 = `cooldown_ms × min(连续失败次数, 5)`——连挂连加长，
  到期自动恢复（"失败定时刷新状态"）；下次选择自动跳过冷却中的候选；
- **全员冷却时半开探测**：宁可试一个冷却最早到期的，也不直接放弃；
- 全员真失败 → 抛 `AggregationFailed`（带每个候选的最后错误），调用方自己决定兜底。

> 权重是使用方的配置（声明），高权重挂了进冷却自然落到低权重——
> 稳定性由 failover 兜底，不由权重许诺。这就是"高权重可以用就先用高权重的"。

## 候选前提与账目

- **候选前提**：使用方对每个候选**有可用支付能力**即可 —— 免费、或已配对的对等
  账户、或已绑定该候选 `accepts` 里的直付渠道（由 `call_agent` 的服务端门禁统一
  判定，语义同 A2A 入口）。补能力本来就是使用方自己的事，聚合器不代劳。
- **账目**：每笔成功调用 = 使用方与真实 agent 的一对一结算（积分/对等账户/直付，
  走该 agent 自己的门禁与验收）。聚合器不留账、不碰钱 —— 三铁律连"间接"都算不上。

## 用法

```python
from a2n_sdk import Client
from a2n_sdk.aggregate import Aggregator

cli = Client("http://127.0.0.1:8000", principal="acct:me")
agg = Aggregator(cli, candidates=[
    {"agent_id": "ag_big",  "weight": 5},   # 主用：又稳又快
    {"agent_id": "ag_mid",  "weight": 2},
    {"agent_id": "ag_back", "weight": 1},   # 兜底
], strategy="weighted", cooldown_ms=30_000)

result = agg.call("fin-strategy", {"ticket": "..."})   # 失败自动换人
print(agg.health())   # 候选健康：本地私账（ok/fail/冷却/RTT 均值）
```

## 与其它机制的关系

- **观测回传**：成功调用的耗时自动进平台的"使用端"口径（`connection.observed`），
  别的使用方在发现页能看到 —— 聚合器的健康数据与平台数据同源不同权：
  平台那份是公开行情，本地这份是我私有的选路依据。
- **SLA 声明 / TTFT 自报 / 探测 RTT**：发现页选候选时的参考；聚合后的实测
  才是我自己的真相。
