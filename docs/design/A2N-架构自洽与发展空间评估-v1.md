# A2N 架构自洽与发展空间评估 v1

> 评估依据：23 个包（最新落地的第 23 包为 `a2n-node` 自持模式）、153 项测试（含 6 项红线测试 + 6 项架构纪律测试）、
> A2A/直付端到端实测（17/17 全绿）。所有结论均可由代码与测试复现，不做印象分。

---

## 一、结论先行

| 维度 | 评分 | 判断 |
|---|---|---|
| 骨架自洽（分层/依赖/装配） | 8.5 / 10 | 结实。依赖单向、装配集中、内核干净 |
| 账本与红线自洽 | 9 / 10 | 最硬的一块，且**有测试守着**，不是口头纪律 |
| 语义自洽（概念/状态/命名） | 6 / 10 | **最大裂缝区**：当时 A2A 入口在治理链之外（**P0-1 已收口，2026-09-14**；分数是收口前的快照） |
| 运行与规模自洽 | 5.5 / 10 | 进程内枢纽 + 单库，与"网络是基础"的愿景有张力 |
| **综合** | **7 / 10** | 骨架比内脏结实，账本比入口结实 |

一句话：**这是一套"账本可信、骨架可扩展、但治理链有断口"的架构。**（2026-09-12 的判断）
最该补的不是新功能，而是把最新接入的 A2A 入口接回治理链。

> 更正（2026-09-14）：这个"最该补的"**已经补完** —— 使用端统一走 `POST /v1/invoke`（治理链唯一入口），
> `/v1/relay` 收口为只服务对等账户的底层原语，控制台不再把它当入口（`tests/test_relay_closure.py` 断言）。
> 上面的评分与结论保留为**收口前的快照**，未重打分。

## 二、自洽的部分（这些是真的，不是自嗨）

1. **三铁律有测试守着**（`test_invariants`）：mint/burn 只能从托管路由进入、
   账本 append-only、**全库无 balance 列**（想存余额都存不了）、
   积分总量 ≡ 托管余额、链哈希可检出篡改。这在国内同类设计里少见。
2. **依赖纪律有测试守着**（`test_architecture`）：只允许声明过的依赖、
   依赖图无环、SDK 零第三方依赖、**支付品牌只出现在 a2n-custodian**
   （本次集成直付时被这条当场拦下来一次——红线真的会咬人）、
   内核不认识任何业务概念。
3. **装配集中一处**（`wiring.py`）：谁订阅谁、谁注入谁，只写一次；
   事件总线 → outbox → 公证 → epoch 锚定是一条真链，不是摆设。
4. **传输阶梯自洽**：节点永远只出站（pull / 隧道 / 中继），
   家宽 PC 零端口暴露也能被公网调用，已实测（含 Docker 多节点）。
5. **结算方式数据化**：`direct_pay:<渠道>`，品牌是数据不是代码。
   以后接任何新渠道，agent 改一行卡片、用户登记一次，**代码零改动**。

## 三、裂缝清单（按严重度）

### P0-1 治理链断口：A2A 入口绕过验收 / 公证 / 信誉 ★最严重

- **定位**：`routers/a2a.py` 中 `publish / acceptance / reputation` 出现 **0 次**。
- **后果**：A2A 是目前唯一面向标准生态的入口（最有流量的入口），
  但它只做"调用 + 记账"——**收了费却没验收、没公证、没信誉、没仲裁入口**。
  A2N 的价值主张是"调用 + 验收 + 多分账"，这里缺了中间那一环。
  一旦发生争议，拿不出 `result_hash` 证据链，仲裁工作台接不住。
- **修法**：`message/send` 先建一等公民任务（复用 `a2n-task`），
  交付后走 `a2n-acceptance`，发事件 → 公证 + 信誉 → 再记账/捕获。
  即"换协议不换规矩"在代码层的兑现。

### P0-2 事实分裂：四张表各说各话，没有统一事实主键

- **定位**：`tasks` / `a2a_tasks` / `deals` / `pay_charges`。
- **后果**：A2A 调用不进 `tasks`，导致对账、仲裁、信誉、公证链全部挂不上；
  同一个"活"在不同表里身份不同，跨表追溯靠人肉拼。
- **修法**：统一事实主键（`task_id` 贯穿四表），A2A 任务视为 task 的一种来源
  （`source = "a2a"`），其余链路按同一主键串联。

### P1-1 直付凭证状态名不副实：CAPTURED 但没人真扣款

- **定位**：`pay_charges.state = "CAPTURED"`，而平台没有调用任何支付网络。
- **后果**：状态撒谎。今天是"记录"，明天接了渠道会变成"真的钱"，
  语义不一致会在对账与争议中放大。
- **修法**：状态机 `AUTHORIZED`（已授权，平台记录）→ 渠道回执回调 →
  `CAPTURED`（真扣款）。回调实现放在 `a2n-custodian`（持牌层）。

### P1-2 工程实现与去中心愿景的张力

- **定位**：`TunnelHub` 进程内字典、SQLite 单库、`X-Principal` 无鉴权。
- **后果**：现在是单实例系统，与"网络是一切基础""不希望有中心服务器"不一致。
- **修法（有清晰路径，非推倒重来）**：hub → Redis pub/sub；
  SQLite → Postgres（store 已是唯一出口，业务代码不动）；
  身份 → DID + 用户私钥签名（AP2 授权链已留好接口，签名字段已有）。

### P2-1 命名漂移与技术债

`/discover/peer-ready` 现在语义是"声明了任一结算方式"（含直付），
名字还停留在"对等账户"；A2A 状态机与 `a2n-task` 状态机两套映射未合一；
`a2n-p2p` 的多跳发现尚未与 registry/transport 合流（目前只用于共识验签）。

## 四、发展空间（天花板在哪，能长到哪）

### 1. 协议面：已经站上潮头，还有两个口子

- **A2A ✓**：标准客户端可直接调用（已实测），Agent Card 发现 + JSON-RPC。
- **AP2 ✓**：intent→cart→payment 授权链已落地，A2N 三个扩展（预算冻结 / 结算凭证 / 问责包）齐备。
- **x402 ✗**：微支付未接。小额高频调用（几分钱一次）用对等账户太重，
  x402 是天然拼图——**这是协议面最大的增量**。
- **用户签名**：凭证目前平台代签并如实标注；接用户 DID 私钥后，
  AP2 问责链即从"结构可验"升级为"密码学可验"，校验代码不用改。

### 2. 网络面：P2P 是伏笔，不是装饰

`a2n-p2p` 已有 ed25519 身份、签名信封、多跳按需发现、TOFU 公钥簿。
缺的是真组播（现为广播）与 DHT。演进方向清楚：
**发现走 P2P（更快、更抗审查），证据走平台（可审计、可仲裁）**——
这与既有传输阶梯完全兼容，不冲突。

### 3. 去中心化的上限：诚实地说，L5 去不掉

| 层 | 能否去中心 | 说明 |
|---|---|---|
| L1 身份 | ✓ | DID + 自签 |
| L2 发现/注册 | ✓ | P2P gossip + 多跳 |
| L3 调度/验收 | ✓ | 可多见证人 |
| L4 账本/公证 | ✓ | 批次 Merkle + ≥2/3 见证签名 |
| L5 资金锚 | ✗ | **唯一去不掉的中心**：人民币持牌托管 or 链上稳定币，二选一 |

结论：A2N 能做成"治理去中心、资金锚单点"的形态。
这已经是合规世界里能做到的最好形态——**别把 L5 也承诺成去中心，那是骗自己**。

### 4. 规模面：路径清楚，工程量可控

store 是唯一数据出口（换 Postgres 不动业务代码）；
hub 是唯一枢纽（换 Redis pub/sub 即可多实例）；
加密/哈希/凭证都是注入式（换实现不动协议）。
**瓶颈不在架构，在工程投入。**

### 5. 商业面：定位干净，变现位清楚

"只发行情不定价、只刻章不碰钱" 让 A2N 天然站在中立位——
它不与客户争利，因此**可以被最大范围的参与者同时信任**，这是最难得的资产。
变现位在托管接口、行情数据、撮合与结算服务，而不是抽成。
（用户已明确：先建系统，不急变现。）

## 五、建议顺序

| 优先级 | 事项 | 解决什么 |
|---|---|---|
| **P0** | A2A 调用升级为一等公民任务，接回验收/事件/公证/信誉 | 治理链断口 |
| **P0** | 统一事实主键，A2A 任务视为 task 的一种来源 | 事实分裂 |
| **P1** | 直付状态机 AUTHORIZED → 渠道回执 → CAPTURED | 状态撒谎 |
| **P1** | hub → Redis、SQLite → Postgres、身份 → DID 签名 | 单实例 → 可扩展 |
| **P2** | x402 微支付、P2P 与发现层合流、行情产品化 | 增量与商业化 |

## 六、一句话判断

**A2N 的设计是可信的，架构是可扩展的，但它现在处于"骨架已立、内脏未连"的阶段。**
三铁律和依赖纪律证明了这套架构有真骨架；
把 A2A 入口接回治理链，是让它从"能跑通"变成"能担责"的那一步。
补完这一步，A2N 才真正配得上"只刻章不碰钱"这句话。

> 更正（2026-09-14）：治理链断口（P0-1）已收口，"内脏未连"的判断需相应修正；但四表分裂（P0-2）与单实例扩展（P1-2）等仍待办，整体仍非"完全收口"。
