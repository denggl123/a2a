# A2N 核心商业价值评估

> 评估日期：2026-09-08
> 评估对象：已建成的 A2N v1.5（23 个包、400 项测试全绿）在真实市场中的商业价值
> 方法：以**已实现能力**为边界（不是纸面设计），按单位经济算账，不回避不成立的假设
> 结论一句话：**A2N 卖的不是"抽成权"，是"可归责性"——它让原本不敢发生的跨主体交易敢发生。但这个价值只能在高客单价场景变现，3% 抽成模型在微调用市场数学上不成立，必须换打法。**

---

## 0. 先给结论

| 维度 | 判断 | 说明 |
|---|---|---|
| 价值是否真实 | **是，且稀缺** | "活干得算不算数"这层确实没人做，且中国监管公约强化了它 |
| 价值能否变现 | **能，但不在原来的地方** | 3% 抽成养不活；订阅制 + 高单价场景可以 |
| 技术是否构成壁垒 | **否** | 23 个包的代码，大厂 3 个月能抄完 |

| 综合 | **值得做，但要靠"算力/专业服务"活着，把 agent 互调当期权** | |

## 1. 价值本体：你到底在卖什么

### 1.1 一句话本体

**跨主体的付费调用今天不发生，不是技术上不能，是因为"出了事谁负责"没人回答。A2N 卖的就是这个答案——可归责性（accountability）。**

拆成四个可定价的交付物：

| 交付物 | 解决的问题 | 谁会为它付钱 |
|---|---|---|
| **验收** | 活交了，但算不算数？ | 使用方（怕白花钱） |
| **不可抵赖的账** | 记的账能不能被对方事后翻脸？ | 双方 + 审计方 |
| **争议裁决证据链** | 打起来时拿什么说话？ | 双方 + 合规部门 |
| **中立方身份** | 谁来判？判的人是不是对手的人？ | 供给方（怕平台既当裁判又当运动员） |

### 1.2 这里有一个容易被忽略的定价权来源

**A2N 的计费单元是"验收过的任务"，不是"API 调用"。**

这是本质区别：

- API 市场（RapidAPI 等）卖的是**调用权**——调了就收钱，结果好不好不管；
- A2N 卖的是**结果**——验收不过不收钱，还全额退回。

这意味着 A2N 能进入"按结果付费"的市场，而按调用计费的平台进不去。对使用方而言，"验收不过不付钱"这一条的感知价值，远高于 3% 的服务费。**这是溢价来源，也是 A2N 唯一真正的定价权。**

### 1.3 还有一个能力是支付巨头做不到的

已实现的**多维计量**（时长 / token / 调用次数分别计价）+ **预算冻结 + 按实结算 + 差额退回**，本质是一个**可变金额的使用量计费合约**。

Stripe、支付宝这类支付通道只能处理"确定金额的付款"。它们不知道这次调用跑了多少秒、烧了多少 token。**A2N 能承载"先授权上限、用多少算多少、算完自动退差额"的合约**——这个能力支付层没有，也不打算有（那是业务层的事）。

## 2. 单位经济：把账算死

### 2.1 分账口径（以代码为准）

```
DEFAULT_SPLIT = { node: 0.90, author: 0.02, fee: 0.03, pool: 0.05 }
1 积分 = 0.01 元
```

- **node 90%**：干活节点的收入
- **author 2%**：能力作者（写 agent 的人）分成——这是 A2N 对供给侧的差异化，大厂商店给不了
- **fee 3%**：平台收入（**这是唯一的变现项**）
- **pool 5%**：激励池，用于冷启动补贴与生态激励（**是成本，不是收入**）

### 2.2 客单价生死线

设持牌方通道成本 = 0.3 元/笔 + 0.1%×金额（这是国内聚合支付的常见量级）：

```
3% × P  =  0.3 + 0.1% × P
2.9% × P = 0.3
P ≈ 10.3 元
```

**结论：单笔低于约 10 元人民币，3% 抽成连清算成本都覆盖不了，每多一笔亏一笔。**

再计入获客与人力摊销，实际可持续的门槛约 **30–50 元/单**。

| 客单价 | 单笔收入(3%) | 单笔通道成本 | 单笔毛利 | 判断 |
|---|---|---|---|---|
| 3 元（x402 笔均水平） | 0.09 元 | 0.30 元 | **−0.21 元** | ❌ 越做越亏 |
| 10 元 | 0.30 元 | 0.31 元 | ≈ 0 | ⚠️ 生死线 |
| 50 元 | 1.50 元 | 0.35 元 | 1.15 元 | ✅ |
| 500 元（GPU 时租/渲染） | 15.0 元 | 0.80 元 | 14.2 元 | ✅✅ |

### 2.3 养活一个团队需要多少 GMV

假设 10 人团队，年成本 300 万 + 云/合规/审计 100 万 = **400 万/年**：

| 场景 | 客单价 | 单笔毛利 | 需要的年单量 | 日均单量 | 对应年 GMV |
|---|---|---|---|---|---|
| 专业服务（翻译/法检/OCR 批量） | 50 元 | 1.15 元 | 348 万 | ~9,500 | **1.74 亿** |
| 算力（GPU 时租/推理/渲染） | 500 元 | 14.2 元 | 28 万 | ~770 | **1.4 亿** |
| 微调用 | 3 元 | −0.21 元 | — | — | **数学上不可能** |

**即：需要约 1.5–2 亿人民币 GMV 才能养活一个 10 人团队（纯抽成模式）。**

### 2.4 对照现实：这个量存在吗

x402 全球一年成绩：1.76 亿笔、约 7300 万美元（≈5.3 亿人民币），笔均 **0.41 美元（≈3 元）**；Artemis 刷量过滤后，**30 天真实交易量仅约 160 万美元**（年化 ≈1.4 亿人民币）。

对照结论：

- **全球** agent 微调用的真实年 GMV ≈ 1.4 亿人民币，且**笔均 3 元，远低于 10 元生死线**；
- 全行业 × 3% = 219 万美元/年，是全世界能分给"网络服务费"的**全部总量**；
- 再除以所有竞争者，A2N 能拿到的很可能是**每年几万块**。

**这一条是本次评估最重要的硬结论：靠 agent 微调用抽成，这个项目活不下去。不是"难"，是数学上不可能。**

## 3. 那价值该在哪里变现：三层收入模型

| 层级 | 场景 | 收费方式 | 为什么成立 |
|---|---|---|---|
| **第一层（现金流）** | **算力调度**：GPU 时租、推理、渲染、批处理 | 3% 网络服务费 | 客单价 100–5000 元，远超生死线；**已有真实付费习惯**，不需要教育市场 |
| **第二层（稳定收入）** | **KYA / 存证服务**（卖 B 端） | 年费订阅 2–10 万 | 2026.8.24 公约要求 KYA 风险分级 + 全链路身份传递 + 可追溯存证；**A2N 的信誉分 + 凭证链几乎是同一套东西的另一块牌子**；客户有合规预算，不是刷量的 C 端 |
| **第三层（规模收入）** | 微调用（<10 元） | **按凭证条数的阶梯订阅**（"刻章费"） | 3% 不够清算成本，改收固定费；收入与客单价塌陷脱钩 |

### 3.1 订阅制的经济账

- KYA/存证：**200 家 × 3 万/年 = 600 万/年**，已覆盖 400 万成本线，且与调用量无关；
- 刻章费：节点月费阶梯（如 ≤1 万条凭证 299/月；≤10 万条 1,499/月），1,000 个活跃节点 × 年均 5,000 元 = **500 万/年**。

**订阅制的关键优势：收入与 GMV 脱钩。** 在 2026-2027 市场未起量的窗口期，这是唯一能让你活到潮水来的收入结构。

### 3.2 为什么"算力先行"是对的

同一套基础设施（账本、验收、凭证链、争议裁决）在算力场景里全部适用，而且：

1. 供给侧现成——大量闲置 GPU（4090 空着也是空着）；
2. 需求侧现成——推理/微调/渲染本就在花钱买；
3. 客单价天然达标；
4. **验收标准最容易定义**（跑完了没、耗时多少、结果哈希对不对），不需要复杂的主观验收。

**算力是现金牛，agent 互调是 2027 年的期权。** 先用算力把这套系统跑两年，等 agent 互调起量时，你的壁垒不是技术，是"已经被审计了 24 个月、一分钱差错都没出过"这个事实。

## 4. 护城河真伪辨析

这是本评估最需要诚实的部分。**大部分你以为的壁垒，都不是壁垒。**

### 4.1 不是护城河

| 你以为的 | 为什么不是 |
|---|---|
| 23 个包的代码、Merkle+SPV、锚定共识 | 都是公开算法，大厂 3 个月能抄完 |
| 多维计量 | 是工程活，不是科学难题 |
| A2A / AP2 集成 | 协议是公开的，谁都能集成（你也没集成得更早） |
| 先发优势 | 市场还没起来，"先发"在无人区没有意义 |

### 4.2 是护城河

| 真正的壁垒 | 为什么是 | 怎么加固 |
|---|---|---|
| **中立性（铁律四）** | 大厂商店（Coze 2000+ 技能、百炼、元器）**物理上做不到**——它们既当裁判又当运动员，一旦自营 agent 就复发信任危机。这是结构性缺陷，不是能力问题 | 把"永不自营 agent / 节点 / 与客户争利"写进对外白皮书，**做成对客户的公开承诺**（违约即失去全部公信力） |
| **审计时长** | "账本跑了 24 个月、零差错"这件事**无法用钱买、无法加速、无法伪造**。新进入者必须重新花 24 个月 | 尽早引入第三方审计并公开报告；把每次对账结果当作资产积累 |
| **见证人网络** | 共识的 ≥2/3 见证权重依赖**真实的、多方持有的钥匙**。见证人越多越分散，收买成本越高 | 尽快让见证人从"本地演示私钥"变成**真实的外部机构**（律所、会计师事务所、高校、行业联盟） |
| **凭证链的司法/审计认可** | 一旦某份 A2N 凭证被法院或审计机构采信，它就成了事实标准 | 主动做存证公证对接、司法鉴定中心合作 |
| **持牌方合作关系** | 中国监管下核心环节必须持牌，持牌方是稀缺资源且有排他倾向 | **这是当前最该抢的资源**（见风险 R2） |

### 4.3 一个必须正视的张力

**中立性与盈利存在天然张力。** 你收 3% fee，就有人说"你判验收通过是为了收手续费"。

对冲方式：
- **收入结构向订阅制倾斜**——订阅费与单笔交易无关，判罚动机就消失了；
- **验收策略开源 + 可插拔**（已实现 `judge()` 策略化）——让使用方能自己验算，不依赖你的结论；
- **争议可申诉、裁定入链**（已实现仲裁工作台）——把"判"的权力从你手里分出去一部分给仲裁员。

## 5. 冷启动：先有鸡还是先有蛋

### 5.1 已建成系统里的冷启动优势

**好消息：A2N 的架构天然降低了冷启动难度。**

- **供给侧门槛极低**：SDK 零第三方依赖，一台家用电脑、一个 4090 就能挂上来；且已解决"无公网 IP 如何被发现"（pull 长轮询 / 反向隧道 / 中继，节点只出站、零暴露）。
- **需求侧不需要先有供给**：本地市场列表是**按需发现**的（不同步全量），使用方搜索时才建立连接，没有"空市场"的观感问题——但这也意味着**第一次搜索必须能搜到东西**，否则流失。
- **激励池 5%** 是现成的冷启动弹药，可用于早期补贴。

### 5.2 真实的冷启动路径（建议）

**不要做双边。** 双边市场同时拉两端是自杀。正确顺序：

1. **单点突破供给**：先签 20–50 个**高确定性供给**（算力节点、成熟的专业服务 agent），保证任何搜索都不落空；
2. **垂直切入需求**：只做一个品类（建议算力，其次 OCR/翻译），把这一个品类的闭环做透；
3. **再用订阅制锁客**：对 B 端卖 KYA/存证，此时你不需要双边网络效应也能收钱。

**关键指标不是 GMV，是"首次搜索命中率"和"验收通过率"。** 前者决定需求侧留存，后者决定供给侧信任。

### 5.3 网络效应有多强

诚实评估：**A2N 的网络效应偏弱。**

- 跨边网络效应（更多供给→更多需求）：存在但不强，因为需求高度垂直（要 OCR 的人不会因为多了翻译 agent 而更想用）；
- **真正的效应在"供给侧声誉资产的沉淀"**：一个节点积累的验收记录、信誉分、凭证链，换平台就归零——**这是锁定效应，比网络效应更可靠**；
- **以及"数据-验收策略"飞轮**：验收样本越多，基线越准，误判越少，使用方越信任。这个飞轮是真实的，但早期需要冷启动数据。

## 6. 竞争：谁能把你挤死

| 对手 | 会不会做你这块 | 做成概率 | 你的活路 |
|---|---|---|---|
| **大厂智能体商店**（Coze / 百炼 / 元器） | 会做结算，但**只能做平台内的** | 中 | 它们封闭且自营——跨生态的中立位它们让不出来 |
| **卡组织/持牌方**（银联 APOP / 支付宝 ACT / 微信 AI 专属卡 / Visa TAP） | **不会做验收**（只做信任与清算） | 低 | **最佳的关系是"被它们集成"而不是竞争**——它们是你的资金锚 |
| **链上派**（x402 + ERC-8004） | 已在做，但**人民币合规路径不通** | 低（国内） | 2026.8 公约下核心环节必须持牌，链上派做不了核心环节 |
| **协议基金会**（Linux Foundation / AAIF） | 不做商业 | — | 保持跟随标准即可 |
| **客户自建** | 大客户可能自建内部结算 | 中 | 但自建解决不了"跨主体互信"——自己给自己盖章没有公信力 |

**唯一真正的死法是：大厂补齐"中立第三方验收"这一层，同时市场也起量了。** 但大厂补不了中立（商业模式下不可能放弃自营），所以这个死法概率不高。

**更现实的死法是：市场迟迟不起量，你在 2028 年之前烧完了。** 见下节。

## 7. 时序：你能不能撑到潮水来

- Juniper 预测 2030 年全球代理商务约 1.5 万亿美元，但 **2026 年仅约 80 亿美元**，且以零售为主（"agent 帮人下单"，不是"agent 调 agent"）；
- 跨组织、跨平台、**需要验收**的付费调用，乐观估计 **2027–2028 才起量**。

**这意味着你需要 18–24 个月的跑道，且这段时间里 GMV 抽成收入接近于零。**

对冲：
1. **现金流靠算力 + 订阅**（第 3 节），不要指望 GMV 抽成；
2. **把这段时间花在积累审计记录上**——每跑一天，你的核心资产（零差错记录 + 见证人网络）就厚一分；
3. **保持小团队**（10 人以内），把成本线压在 400 万/年以下。

## 9. 价值兑现度：已建成的 23 个包里，哪些直接对应钱

| 包 | 与商业价值的关系 | 状态 |
|---|---|---|
| `a2n-acceptance` 验收 + 争议 | **核心价值本体**（"算不算数"） | ✅ 已实现（含容差策略、自动开单） |
| `a2n-notary` 凭证链 | **核心价值本体**（不可抵赖） | ✅ 已实现 |
| `a2n-ledger` + `a2n-settlement` | 价值载体（账 + 分账 90/2/3/5） | ✅ 已实现 |
| `a2n-consensus` 锚定共识 | **可信度资产**（可被第三方核账） | ✅ 已实现（但见证人待外部化，R3） |
| `a2n-reputation` + KYA 潜力 | **订阅制收入的载体** | ⚠️ 信誉已实现，**KYA 包装未做** ← 高价值待建 |
| `a2n-ap2` | 接入支付巨头生态的门票 | ✅ 已实现（翻译层） |
| `a2n-transport` / `a2n-p2p` | 供给侧冷启动的前提（无公网 IP 可接入） | ✅ 已实现 |
| `a2n-custodian` | 资金合法性 | ⚠️ **Mock，R2 未解** |
| 其余 | 必要成本，不直接产生收入 | ✅ |

**最高价值的待建项：把 `a2n-reputation` + `a2n-notary` 包装成 KYA 合规产品（风险分级 + 全链路身份传递 + 可追溯存证），这是唯一能在 2026 年就收到钱的东西。**

## 10. 结论与建议打法

### 10.1 一句话定位（建议对外口径）

> **A2N 是 agent 经济里的"登记结算公司 + 公证处"——不碰货、不碰钱、只盖章。**

不是"agent 版淘宝"（那是 Coze 的位置，你打不过），而是让跨主体的付费调用**敢发生**的那一层。

### 10.2 打法

| 时间 | 目标 | 关键动作 |
|---|---|---|
| **0–90 天** | 拿到合法性 + 第一笔订阅收入 | ① 签一家持牌方（R2，最高优先级）；② 算力品类跑通闭环；③ 把信誉+凭证包装成 KYA 产品，签 3–5 家 B 端试点 |
| **3–12 月** | 现金流自足 | ① 算力 GMV 冲 5,000 万；② KYA 订阅 50–100 家；③ 见证人外部化（律所/会计师事务所/高校），≥5 家真实机构 |
| **12–24 月** | 积累不可复制的资产 | ① 引入第三方审计并公开"零差错"报告；② 推动至少 1 份 A2N 凭证被司法/审计采信；③ 保持小团队，等 2027-2028 agent 互调起量 |

### 10.3 最后一句

**这个项目的价值不在抽成比例，在于当行业需要一个"谁都不信任的中立方"时，你的账本已经被审计了两年，而且一分钱差错都没出过。**

那才是别人买不走的东西。但同时请记住第 2.4 节的账：**在微调用市场里，这个价值一分钱都变不出来。** 找到客单价 ≥ 50 元的场景，或者干脆改收订阅费——否则所有精巧的设计都只是在给一个数学上不成立的模型做工程优化。
