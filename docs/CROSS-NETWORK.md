# 跨网络双机：下一道门槛与它的核对方法

这份文档只讲一件事：GPT 在 2026-09-27 评估里点出的那道门槛，**现在到了哪一步**、
**怎么一条命令复现**、以及**还差什么才算过**。写得尽量具体，避免把"看到了"
说成"做到了"。

## 门槛原话

> 两台不在同一网络的普通电脑，各自安装节点；一方挂真实 Agent，另一方自主发现并
> 完成免费调用，双方都能核验同一笔收据，断线重启后仍可继续。

这比"打开控制台、搜到卡片"高一级：要的是**一条不可作假的证据**。

## 现在到了哪一步（2026-09-27 实测）

| 环节 | 状态 | 证据 |
|---|---|---|
| 两台不同网络的节点都在跑 | ✅ | 本机 Windows 节点（家庭网，8890）+ 公网数据中心节点（`172.245.148.171`，systemd） |
| 跨网络**发现** | ✅ | 本机节点经 HTTPS 从公网目录搜回远端卡（`did:a2n:ag_4c356c85…`），`errors=[]` |
| 跨网络**免费调用** | ❌ | 远端调用 `state=failed`：`URLError: Connection refused` / `a2nState=UNREACHABLE` |
| 双方核验**同一笔收据** | 待调用成功 | 无交付 → 收据为 `null`（**不伪造**，正确行为） |
| 断线重启可继续 | 未测 | 依赖上面一步 |

**为什么调用失败**：远端那份供给的**上游是被故意留死的**（`A2N_DEAD_AGENT=
http://127.0.0.1:9/invoke`）。节点**真的**去连、连不上的真实错误**原样上报**。
这不是脚本故障，是产品要说的那句话：**卡在架 ≠ 服务活着**。要跨过这道门槛，
远端必须挂一个**真能跑通的 Agent**。

## 怎么一条命令复现

**调用方**（在任意一台装好节点的机器上）：

```bash
python scripts/cross_network_check.py \
    --node http://127.0.0.1:8890 \
    --source https://<远端节点的公开入口> \
    --skill <能力标识> \
    --call
```

它会逐条打印「连接目录源 / 跨网络发现 / 选中远端卡 / 加入待使用 / 远端调用 / 读回收据」
的 PASS/FAIL，并把**真实错误原样**打出来。脚本自己从 `/console` 取本机 cookie，
不需要配对码。

**节点自检**（装完跑不起来、或发现不到别人时）：

```bash
python scripts/node_doctor.py --home data/local-node --source https://<远端公开入口>
```

## 还差什么才算过

1. **远端挂一个真能跑通的 Agent**（不是死上游）。它可以是任何真实的
   HTTP/A2A 服务；把它的地址作为那份供给的上游即可。
2. **调用方**用上面的命令发起免费调用，拿到交付结果与收据哈希。
3. **双方核验收据**：调用方读本机留存（`/v1/calls/detail`），供给方读自己那份，
   两边应是**同一笔**（同一个 `task_id` 与收据哈希）。
4. **断线重启**：把任一台节点的进程杀掉再起，重复第 2–3 步，仍应成立。

## 诚实边界（必须说清，不能含糊）

* **原生 P2P 那条腿现在不通，且不是代码问题**。本机 VPN 是**代理模式（无 TUN）**，
  原生 UDP 出得去、回包丢：对端能看到 `{verified_envelope_key:true, reachable:false}`
  且 `dropped_*` 全 0。要让它通得把 VPN 切到 **TUN / 全局模式**，属网络形状。
* 因此上面这条证据链走的是**HTTPS 公开入口 / 目录源**这一路，**不是原生 P2P**。
  别把"经隧道的 HTTPS 调用"说成"P2P 已打通"。
* 本机环境的**代理端口是会话级的**（会变、会失效）。节点出网若继承了失效代理，
  跨网络那一跳会**时通时断**；`cross_network_check.py` 默认重试 3 次并如实记录抖动。
