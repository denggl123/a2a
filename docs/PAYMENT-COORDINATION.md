# 支付协调层（原生币、x402 与积分已实现，2026-10-08）

2026-10-09：增加供应方支持列表、使用方付款顺序和有额度的自动结算。详细规则见[对等账户自动匹配与结算](AUTOMATIC-SETTLEMENT.md)。本页中的逐笔确认流程仍可使用；自动模式以所有者事先保存的明确规则授权。

## 业务目的与层级

每个完整 SDK 节点独立完成支付条件协商、付款与事实核对。平台抽佣恒为零；原生币与 x402 方式的资金从买方钱包直接到卖方钱包。公共发现协作依旧是节点义务；钱包、付款额度及收款通道由节点所有者配置。积分已作为独立支付子模块接入，其发行、持有、欠账、自愿兑换与恢复规则见 [积分模块](POINTS.md)。积分交易不要求配置钱包。

【2026-10-08 已确认的责任边界】支付协调属于**协调层**。网络协调负责发现身份、供给和通路；支付协调接收业务层提交的结算意图，选择双方接受的支付能力并编排结算。原生币、x402 和积分分别通过独立支付子模块执行自己的规则。支付协调不改变网络发现算法，也不形成中心资金账本。

业务层决定是否需要结算，前十次样品直接走免费业务流程，跳过支付协调的结算流程及所有支付子模块，不创建零金额支付订单。普通服务的“免费但产生供应方积分”仍有积分记账，须由业务层发起结算意图。支付子模块不读取样品计数、不决定试用资格，也不执行 Agent。

**当前实现**：节点 `TradeService` 已独立承担业务询价、免费资格、接单和 Agent 调用。`PaymentService` 负责原生币与 x402 交互和通道编排，其旧业务入口委托 `TradeService`；积分由 `PointsPayment` 编排，`PointsNode` 和 `PointsBook` 只执行积分协议及账本。免费业务条件不会进入支付报价器，也不会创建积分或其他支付订单。

## 双边交易规则

1. 买方签名查询包含交易双方 DID、商品、技能、任务号、规范化输入摘要、已配置能力和钱包持有证明。
2. 卖方业务服务检查自己的真实免费资格与价目表；需要结算时再查询实际可用支付通道并返回签名报价。前 10 次技术交付仍免费并强制公开脱敏样品，跳过任何结算；质量评价不影响计数。配置钱包或积分政策不会提前结束试用。免费报价与执行均由 `TradeService` 完成。
3. 本版本收费报价仅支持已声明的固定 `call_count / per=1` 单次价格。未标价、尚无共同通道、计量型收费没有可执行的报价，不能默认为免费或静默换币。
4. 可协商选项必须在双方方法、链、资产、币种、支付时序的交集中。x402 收款还要获得结算服务 `/supported` 的明确支持。
5. 买方明确选择选项、网络费上限。计划固定报价、金额、币种、链、资产、收款方、付款方、技能、商品版本、输入摘要、时序和平台手续费零。双方节点签名绑定钱包持有证明。
6. 卖方业务服务接受时冻结接单资格；如果此时应免费，就拒绝收费接受，要求走免费业务条件。买方本机按所有者额度预留资金后生成 READY 付款尝试。
7. 单独接受计划不会付钱。逐笔模式由买方明确付款；自动模式由已授权的自动调用入口按固定计划付款。直接转账由卖方独立核验原交易后才接收费调用。x402 调用时签授权，卖方先验签及验证授权，再执行一次 Agent 并结算。
8. 同一交易 UID 只有一个付款订单；订单包含历史尝试。每次尝试单独持久化。未知、正在提交、正在查询和已确认的尝试不能更换通道或再签付款。
9. READY 可以显式取消。取消先固定本机结果，再发送买方签名撤销并取得卖方签名收件。撤销之前的计划不能再授权调用；新计划仍需双方接受。
10. 接受/撤销的响应丢失时可以发送同一份签名记录；不会另造支付授权。确定失败才允许新尝试。原通道查询是 UNKNOWN 的唯一恢复方向。

同一订单的商品版本、技能和输入永远不能更换。原任务已经交付、原付款确定失败时，可以协商直接转账补付款，读取原交付；不会再次执行 Agent。执行结果仍未知时，必须先恢复原交付，不能用换支付方式重新启动任务。免费原交易不能事后改成收费交易。

查询及报价有效期至多 300 秒。签名和固定计划会在执行时再次检查。协调调用输入上限 64 KiB；公开支付入口请求上限 256 KiB；x402 原协议响应上限 1 MiB。每节点同时有效报价上限 512，同一买方 16。普通 A2A 原有能力保持自己的限制。

已经被卖方接受的原计划可以在确认响应丢失后恢复同一份签名收件，即使报价后来过期；过期计划不能新付款，需要先取消再重新询价。控制台显示确认中断的计划、付款订单及卖方收到的约定。公开询价只传输入摘要，可使用现有节点的 HTTP 发现路由；付款授权、完整输入与私有取件凭据传输默认要求 HTTPS，仅所有者明确开启本地测试时允许 HTTP。

### 通道设置与原订单

设置变更创建一个新的通道版本，新报价使用新设置。未付款的接受凭证不会无限锁住收款设置；有支付暴露、未知付款或已确认付款时，也保留其原通道用于核对和退款。每个订单绑定的原钱包、链、资产、RPC、安全传输设置及驱动版本不会随设置变更而替换。旧钱包密钥继续保存在本机加密账本中，API 不返回密钥。

卖方接受凭证单列 OPEN、EXPIRED、EXPOSED、REVOKED、FULFILLED 等授权状态。电脑时间到期仅禁止新的付款授权，不证明原付款失败，不释放未知资金风险，也不阻止核验晚到的原付款。有效及暴露中的接受凭证受每节点 512、每买方 16 的数量上限约束。

本次升级前已有的订单按升级时仍可取得的设置绑定通道版本；无法恢复此前已经被其他程序覆盖且未保存的旧配置。升级后保留的原通道可以在钱包轮换、关闭当前通道和节点重启后继续核对原单。移除当前能力不会自动清理原通道或原钱包。

## 通道执行与恢复

### 原生币直接转账

- EVM EIP-1559，网络使用 CAIP-2 `eip155:<chainId>`；金额和网络费均为该原生币最小单位整数。
- 仅接受 EOA 收款地址，避免普通付款意外执行合约。交易 calldata 绑定计划摘要，别人给同一收款地址的交易不能充当这笔付款。
- 实际估算 gas，限制最多 200000 gas，并遵守明确批准的最大总网络费。金额和费用上限一起占用预算。
- 同一钱包的签名序号在加密账本事务中串行分配，即使旧订单与新通道版本并存也共用序号预留；完整已签交易、hash、nonce、计划绑定先加密落库，再广播一次。
- 广播超时或 RPC 拒绝不能证明交易未发生。此时保留 UNKNOWN，只查询原 hash；程序重启也不重新广播。
- 核验链号、交易 hash、付款方、收款方、金额、计划 calldata、规范区块 hash、receipt 和确认深度。确认成功后按实际网络费记支出；确定失败且已耗费 gas 时仍记录实际 gas 支出。
- 外部钱包操作同一地址可能造成 nonce 冲突或等待。节点不会为解决冲突自动产生新付款或提高费用。

### x402

- 支持范围为 v2、exact、EVM、EIP-3009、EOA、authorization flow；不把 Permit2、Solana、escrow 或其他时序冒充为已支持。
- 付款签名暴露之前持久化；同一计划固定唯一授权 nonce。换 nonce 的重复请求被协调层拒绝，即使它有有效签名。
- `/verify` 和 `/settle` 适配标准服务，但到账状态由独立 EVM RPC 的事件、receipt、规范区块和确认深度判断。
- 默认买方网络费为零；实际链 gas 由结算服务提交者支付，结算服务的其他收费必须另行约定，不能当作平台免费。
- 交付执行后结算响应丢失，双方都保留付款和交付事实。买方通过自己的节点签名及原私有取件凭据请求恢复；卖方只核对链和读取缓存，绝不重跑 Agent 或重新结算。
- 恢复结果再经过双边收据和接单合同核验，并写回原调用。已交付但付款仍 UNKNOWN 可以独立显示。
- 过期授权只有在确认区块时间、完整事件扫描和未使用状态均满足时，才可判定确定失败。仅电脑时间到期不释放风险额度。

链上确认依赖所有者配置的 RPC。节点核验的是该链服务提供的规范链事实，本版本不是独立全节点共识客户端。

## 退款

退款必须有原交易、原付款确认、双方签名且 BOTH_ACCEPTED 的 REFUND 方案和卖方明确执行。退款金额、币种、双方钱包从原付款和签名方案推导，不能由请求参数任意替换。

退款是新订单，绑定原交易及方案摘要。累计已确认或未确定退款不能超过原付款。重复方案使用原订单；未知退款只核对原通道。

- 原生币付款：独立 EIP-1559 逆向转账，卖方单独批准网络费预算。
- x402 付款：独立 EIP-3009 逆向授权，由卖方配置的结算服务完成代币转账；不重新执行任何 Agent。卖方代币额度需要事先配置。
- 积分 PAY：按原单最终收到的发行方积分逆向转移；双方签名方案绑定原交易及币种，累计退款不可超过实收积分。EARN 没有原付款可退，DEBT 的补偿可通过主动加分和还账完成。
- 买方收到卖方签名通知后，独立核验逆向交易或授权事件。通知失败可以再次核对原退款；不会重复付钱。

付款、退款、交付和质量评价互不覆盖。部分退款只表示该退款方案已经付款，不等于原单全部退回，也不会自动宣布质量评价失效。

## API

本机接口均要求本机管理认证；钱包和预算设置不在公共入口提供。钱包文件口令用于导入加密 keystore，密钥只写入现有加密账本；API 不返回密钥。默认钱包和额度都未配置。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/v1/payment-coordination` | 通道、订单、尝试、钱包地址和退款摘要 |
| POST | `/v1/payment-coordination/configure` | 配置 native/x402、可选加密 keystore 与口令 |
| POST | `/v1/payment-coordination/budget` | 精确整数额度与配置修订 CAS |
| POST | `/v1/payment-coordination/quote` | `{projection_id, request}`，请求固定输入报价 |
| POST | `/v1/payment-coordination/prepare` | `{offer_id, option_index, fee_cap_minor, command_id}`，显式接受并预留 |
| POST | `/v1/payment-coordination/free-execute` | `{offer_id}`，调用免费条件 |
| POST | `/v1/payment-coordination/plans/{id}/accept` | 恢复同一份接受交互 |
| POST | `/v1/payment-coordination/plans/{id}/pay` | 明确原生币转账 |
| POST | `/v1/payment-coordination/plans/{id}/execute` | 已付款调用，或明确 x402 授权与调用 |
| POST | `/v1/payment-coordination/plans/{id}/reconcile` | 原付款与原交付核对 |
| POST | `/v1/payment-coordination/plans/{id}/cancel` | 提交前取消及签名撤销 |
| POST | `/v1/payment-coordination/refund` | `{proposal_id, fee_cap_minor}`，明确退款 |
| POST | `/v1/payment-coordination/refund-reconcile` | `{proposal_id}`，核对原退款 |
| POST | `/v1/trades/{quote,free-execute,prepare}` | 通用业务询价、免费调用、明确选择结算方式；控制台使用这些入口 |
| POST | `/v1/trades/plans/{id}/{execute,reconcile,cancel,pay}` | 按原计划操作；积分与其他方法由已固定方式分派 |
| GET / POST | `/v1/points`、`/v1/points/*` | 独立积分账户、政策、加分、兑换、还账与核对；详见积分模块接口表 |
| POST | `/public/v1/trades/{quote,points-recover}` | 签名业务询价及原积分服务交付恢复 |
| POST | `/public/v1/points/{catalog,balance,consent,prepare,apply,status,decision}` | 积分签名协议；管理设置不公开 |
| POST | `/public/v1/payments/{quote,accept,revoke,observe,execute,recover,refund-observe}` | 双边签名协议或 x402 资源入口 |

示例配置（钱包另通过加密 keystore 导入，示例地址需自行填写）：

```json
{
  "config": {
    "native": [{"currency":"ETH","network":"eip155:84532","rpc_url":"https://你的RPC","confirmations":3}],
    "x402": {"assets":[{"currency":"USDC","network":"eip155:84532","asset":"0x实际代币合约","name":"实际EIP712名称","version":"2","rpc_url":"https://你的RPC","confirmations":3}]},
    "facilitator_url":"https://你的结算服务"
  }
}
```

RPC、代币合约及 EIP-712 域必须真实匹配。没有相应配置就声明未配置，不显示为可付款。

## 验证及后续扩展边界

原生币、x402 和积分已接入[独立加密结算协调通道](SETTLEMENT-TRANSPORT.md)，供给方及使用方只有出站连接时仍能按原计划协商、核对交付和回传退款。中继只转送密文，链 RPC/facilitator 与各子模块授权规则保持原边界。

测试包括真实私有 EVM 原生币交易、广播响应丢失、重启核对、两节点收费调用、首 10 次免费样品、取消再选择、独立退款、x402 双边收据与缓存交付恢复。测试币没有现实价值，不使用主网资金。

x402 集成检查部署测试用 EIP-3009 合约，经实际 HTTP 结算服务提交链上交易，并以双方代币余额验证付款和逆向退款。大于 JavaScript 安全整数范围的退款金额经本机 HTTP、签名交换及精确文字显示验证；签名协议仍使用整数金额。生产镜像不含私有链测试依赖。

复现私有链检查：先安装项目与 `requirements-test-payment.txt`，运行 `pytest tests/test_payment_coordination.py tests/test_paid_market.py tests/test_payment_channel_lifecycle.py tests/test_resolutions.py`。构建 `a2n-node-test` 镜像后，也可运行 `python scripts/check_payment_docker.py`；该脚本只向临时检查容器安装测试依赖，账本和钱包均与现有四节点隔离，容器退出后删除。

积分补充了供应方真实服务发行、主动加分、欠账及归还、两方至三方循环兑换、最多三跳自愿接受路径、断线后的原决定恢复与独立退款。新增方法实现注入端口、真实能力声明、精确观测与确定失败条件后，再接入同一协调边界及交易事实。法币、其他链、托管、支付后计量、链上多跳代付和创作者分成尚未实现；积分兑换能力不代表支持这些支付方法。

标准依据：[Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/)、[EIP-1559](https://eips.ethereum.org/EIPS/eip-1559)、[EIP-3009](https://eips.ethereum.org/EIPS/eip-3009)、[x402 v2](https://github.com/x402-foundation/x402/blob/main/specs/x402-specification-v2.md)。
