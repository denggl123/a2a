# 上架名额：「允许被发现的数量」

> 一句话：供给方声明"我同时最多让几个使用者发现我"，平台照着执行 ——
> 它压的是**同时在用的人数**，不是累计来过的人次。

对应代码：`packages/a2n-registry/src/a2n_registry/seats.py`、
`agents.discover_limit` / `discovery_seats`（`a2n-store/db.py`）。

---

## 1. 它是什么，不是什么

| | 是 | 不是 |
|---|---|---|
| 性质 | 供给方的**分发意愿**（与 `visibility` 同族） | 能力声明（"我能扛多少并发"） |
| 谁执行 | 平台（按使用者占名额、闲置自动释放） | 供给方自己（自报容量平台验不了） |
| 落在哪 | `agents.discover_limit` + `discovery_seats` | **卡里** |
| 影响 | 谁能**发现**它 | 谁能**调用**它（那永远由门禁判） |

**为什么不写进卡**：卡的自证签名域 = 整张卡。平台往里写一个字段 → 整卡哈希变 →
签名当场失效。所以"平台会改的东西"一律不进卡。反过来，供给方**自己签的卡**里
可以声明 `x-a2n.discover_limit`，注册时由平台采纳为初值（那一份是它自己签的）。

**为什么不是"并发额度"**：`sla.max_concurrent` 是自报的容量承诺，平台验不了，
早被移出网络事实（见 `a2n_registry.service.deployment_of` 的注释：能力是黑盒）。
名额不一样 —— 它说的是"我愿意被几个人找到"，平台只需要**执行并如实展示**。

---

## 2. 三条语义

1. 按**使用者**（principal）计名额，一人一个；重复调用只**续期**，不叠加。
2. 占用发生在"**建立调用关系**"那一刻（建任务），不是"被浏览到"那一刻 ——
   看客不该耗光名额。这就是"**间接**控并发"的意思。
3. 闲置 TTL 到期即释放（默认 1800 秒，`A2N_SEAT_TTL_SECONDS` 可调）：
   约束的是**同时**，不是累计 —— 一个名额可以被下一个人接着用。

---

## 3. 满员怎么表现（三处必须一致）

| 位置 | 表现 |
|---|---|
| 发现（`discovery.query`、`GET /v1/registry/agents?scope=all`） | 对**未持有者**不再返回；对**已持有者**照常返回（正在用的东西不能凭空消失） |
| 派单 / 建单 | 预检 `discovery.assignable` + 建任务事务内原子 `seats.take`；抢不到**整体回滚**（不留任务、不冻预算） |
| 直接点名（`GET /v1/registry/agents/{id}`） | **仍 200**，`seats` 写清「3/3 已满、新使用者暂时发现不到它」 |

不做"悄悄降权"这种中间态：要么看得见（且可调用），要么解释得清为什么看不见。

**可见性判据只有一处**：`a2n_registry.seats.expose`（visibility 三态 + 名额）。
发现层与控制台名单都问它 —— 两个接口各写一遍，迟早对"能不能被发现"给出两种答案。

---

## 4. 接口与界面

| 入口 | 形态 |
|---|---|
| 上架 | `POST /v1/registry/agents` 带 `discover_limit`（0 / 不传 = 不限） |
| 改上架 | `PUT /v1/registry/agents/{id}/listing`（`visibility` + `discover_limit`，**仅 owner**） |
| SDK | `shelf(..., discover_limit=N)`、`client.set_listing(...)`、CLI `--discover-limit` / `set-listing` |
| 投影 | `seats = {limit, used, left, full, unlimited, mine, ttl_seconds}`；占用者名单 `holders` **只给 owner** |
| 控制台 | 上架表单有「允许被发现的数量」；自售列表与发现页挂「名额 已占/上限」徽标；明细里给占用者 |

"改卡"与"改上架"刻意分成两条路：卡是供给方自签的**内容**（改它要重签、重算 hash），
上架信息是**分发策略**（平台执行、平台记）。并成一条路，改个名额就得重签整张卡。

---

## 5. 边界（明确不做的事）

- **不参与排序**：与价目同一条红线 —— 排序只用第三方验证过的事实。
- **不是调用资格**：能不能调永远由服务端门禁（`gate.resolve`）判，界面绝不一刀切。
- **不永久占有**：只有闲置释放；也**不**在任务终态立即释放 ——
  刚交付完的人很可能马上再来一单，把他踢出名额反而制造抖动。
- **与 `visibility` 正交**：unlisted / private 本就不进公开名单，名额只管公开那部分。
- **0 / 缺省 = 不限**：老 agent 的上架行为一个字不变（向后兼容）。

## 6. 验证

- `tests/test_seats.py`：限额生效 / 满员对新人不可见但对持有者可见 / 一人一额（续期不叠加）/
  闲置释放后可复用 / 派单硬拦 / 满员下单整体回滚（无任务、无冻结）/
  **并发抢最后一个名额恰好一人成功** / 形状校验（负数、bool）/ 占用者名单只走显式请求 /
  HTTP 改上架只有 owner 能改
- 活库核验 ⑫：演示免费档声明的 3 真的落了库、到了接口；限额与不限两种情形各有明确形状
- 控制台四层体检：② ⑮ 组（表单字段 + 保存走 `/listing` + 徽标判据）、
  ③ 真渲染（发现页显示「名额 已占/上限」）
