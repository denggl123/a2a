## 实际发现与调用

- 所有 20 个有向组合逐级发现目标供给、导入签名 Card、调用实际算术 Agent，并核对结果 42、收据身份与结果摘要。
- 服务器调用四个私网节点，实际使用节点主动维持的密封中继路径。
- 验收每轮额度为 64 次远程操作、4 MiB 响应、60 秒网络 I/O、8 级引荐、256 个候选；需要时在同一搜索中继续有限轮次，没有修改产品默认额度。
- 测试覆盖 **两台物理机器/两个网络环境**。Windows 与三个 Docker 是四个逻辑节点，尚不能视为五台独立电脑或五家运营商。

## 本轮修复

| 问题 | 修复边界 | 验证 |
| --- | --- | --- |
| 初次签名回复丢失后缺少远端任务编号 | 独立注入原编号解析接口；仅处理保存且验真的 signed-a2a / sealed-relay 目标，查询原任务；第三方 A2A 不猜编号 | 直接及多节点中继故障注入，旧记录实际恢复，执行和样品只计一次 |
| Windows DPAPI 解密持续占用内存 | 复用 ctypes 原生结构及指针类型，初始化时固定参数类型，保留加密格式兼容性 | 修复前千次解密增加千个缓存类型；修复后万次不增长，并发回归通过 |
| FIND 摘要与稍后 GET_CARD 不一致 | 固定精确签名卡片；缓存限 512 项、8 MiB、300 秒；游标过期有限重读两次，保留额度和候选 | 租约刷新、摘要与身份匹配、过期容量、真实 SDK 分页测试及新版五节点发现通过 |

整个项目 **712 项 pytest 测试通过，退出码 0**。[源码测试](server-beta6-source-tests.json)、[Windows 资源验证](windows-dpapi-resources-2026-10-11.json)、[原回复实际恢复](server-beta4-original-recovery.json)。

大型 SSH 管理响应曾截断，私有验收管理桥改用压缩响应和 SHA256 校验。正式 SDK 客户端读取上限为 16 MiB；这里不将截断误写为 SDK 有 256 KB 管理读取上限。
