# Windows 重复启动异常修复

日期：2026-10-06。

## 问题与原因

截图中的异常为 `RuntimeError: 这个节点目录已经有运行中的实例`。当前节点日志同时出现两种调用栈：直接创建 Daemon 时获取 `runtime.lock` 失败，以及旧启动器等待该锁 10 秒后失败。

现场存在两个登录启动来源：`A2N-Node` 计划任务和当前用户的 `A2N Node` 登录项。节点尚未开放 HTTP 时，旧代码会把“健康检查尚未通过”直接解释为可以新建节点；节点重启时，多个等待者又会各自尝试获取、释放存储锁后启动。另一实例抢先启动会使等待者抛出未处理异常，由 Windows 单文件程序显示截图中的错误窗口。

## 修复

1. 同一目录通过 `desktop-launcher.lock` 选出一个桌面启动器。其他入口等待本机节点就绪，核对目录后正常复用并退出。
2. 增加 `HomeInUseError`，仅对锁竞争做等待处理。`runtime.lock` 仍由 Daemon 在完整运行期间持有，保留离线恢复的互斥保护。
3. 启动器在节点启动或停机期间持续检查实际健康状态，并直接由 Daemon 原子获取存储锁。等待 30 秒仍未就绪则写日志、返回状态 2。
4. 升级接管前释放启动器锁，再检查已安装程序的固定哈希，使替换程序能够接管。
5. 一次 HTTP 响应同时判断节点健康状态和目录归属，避免停机发生在两次探测之间时误判目录。
6. 默认后台启动经过相同的桌面入口；节点已经就绪时优先识别可复用的节点，再处理子启动器退出状态。
7. 兼容计划任务循环仅重试非正常退出；正常复用或主动停机后退出。
