# 愿景兑现情况复核（2026-10-09）

## 1. 评估范围与结论

依据用户历次确认的愿景，对照当前源码、设计文档、最近验收记录，以及本轮对 Windows 和三个 Docker 常驻节点的只读查询。排除底层跨电脑、跨网络、NAT、公网路径及第五台服务器的网络测试。

目标仍是非盈利的 Agent 供需交易市场：节点即平台，人人提供有界公共发现；重信誉、轻证据，允许有限单笔损失；前十次免费交付固定公开为样品且完全绕过结算；发现与业务筛选分离；支付由协调层装配独立子模块；安装完整 SDK 后具备整套功能。

当前已具备可实际运行的核心业务闭环。剩余工作主要是让普通用户更容易找到和使用合适的成熟 Agent、扩大可交付服务类型，以及证明信誉和质量算法在持续真实使用中的效果。不能用一个完成度百分比同时代替代码能力、部署状态和生态成熟度。

## 3. 仍有明确实现缺口

### P1：样品能公开，但正常内容会被误隐藏

- `privacy.py` 将字段名含 `token` 一概作为秘密字段处理。
- 本轮读取实际文档 Agent 的公开样品，`redactions` 包含 `token`、`token_rule`、`tokens`；正常词频中的词、分词规则和数量都受影响。
- 这会削弱用户通过样品判断 Agent 的能力，应优先修正字段语义和内容识别边界，保留真正凭证的脱敏。
- 前十次强制公开规则继续执行；修复不应引入供应方可随意隐藏样品的开关。

证据：`packages/a2n-sdk/src/a2n_sdk/privacy.py:60`；`project-vision-audit-state-2026-10-09.json`。

### P1：找合适 Agent 的普通用户流程还不够完整

- 当前匹配主要依赖技能、标签、语言、输入输出类型等声明字段，用户仍需手动表达和调整条件。
- 自然语言需求到结构化条件、结果比较到选用的连贯流程尚未完成；其解析应留在展示/推荐侧，不改变公共发现规则。
- 后端支持自定义 `task_class`，排序页面目前只提供任务规模、输出、语言和评审口径，无法直接选择自定义任务类别。本批文档盘点类别可以通过接口排序，但普通页面的任务口径选择尚未完整接通。
- 缺少“前几名是否被选用、找到合适供给花了多久、使用后是否满意和再次使用”的本机效果记录与汇总，尚不能证明推荐越来越适合本人。
- 使用历史自动学习偏好属于后续可选增强；现有显式权重和偏好设置可以继续使用，不需要强制自动学习。

证据：`packages/a2n-sdk/src/a2n_sdk/selection/scoring.py:126`；`packages/a2n-sdk/src/a2n_sdk/web/selection.js:82`；`docs/PERSONALIZED-AGENT-SELECTION.md`。

### P1：复杂任务的质量评审覆盖不足

- 当前客观检查是有界 JSON/文本规则，人工风格的体验评分另行保存；这些适合结构和基本要求检查。
- 对“代码是否实际通过独立测试、文档内容是否正确、图片是否符合需求”等，尚无独立受控执行/专业评审器。
- 图片、音视频及复杂成果尚无完整任务口径与评审适配。若接入语义评审，应可选、明确来源和权限，不能把供应方自报结果当作独立证据。
- 应沿用独立评审端口与适配器，避免质量模块直接依赖支付、发现或交易执行内部结构。

证据：`docs/TASK-QUALITY-CALIBRATION.md:34`；`packages/a2n-sdk/src/a2n_sdk/task_quality/`。

### P2：复杂成果与流式服务的使用体验不足

- 有私有文件交付和小图缩略图，但没有完整的音视频预览、复杂文档预览及对应的公共样品投影。
- 单文件上限为 16 MiB，本机资产总量上限为 128 MiB；视频和较大工作流成果容易超出当前范围。
- 当前交互时间记录是非流式总等待时间；首个有用输出尚无真正流式观测，不能把总耗时当成首段输出延迟。
- 图像缩略图去除元数据已有；图像内容、音视频内容的自动脱敏尚未覆盖。复杂媒体需要独立公开摘要规则，不能直接把私有原文件全量公开。

证据：`packages/a2n-sdk/src/a2n_sdk/assets.py:11`；`packages/a2n-node/src/a2n_node/asset_service.py:71`；`packages/a2n-sdk/src/a2n_sdk/calls.py:147`。

### P2：安装成熟工作流的能力还有限

- 当前可安装包是受限 WASM 模块；已经运行的外部 Agent 可以通过 HTTP/A2A 接入。
- 尚没有把通用 Python 服务、模型依赖、GPU/容器工作流等打成同一套可安装、升级和回滚的 Agent 包。
- 若希望使用者安装别人的成熟工作流并重新提供服务，需要补执行后端、依赖声明、资源要求与生命周期；不应另建第二套供给/交易账本。

证据：`packages/a2n-sdk/src/a2n_sdk/agent_packages.py:12`；`docs/VISION-IMPLEMENTATION.md:96`。

### P2：长期维护和正式发行还需补齐

- 备份与恢复已具备，但未形成普通用户可配置的定期备份、容量提醒和长期归档流程。
- 任务评审计划最多 5,000 个，试算模型最多 128 个；当前明确拒绝超限，没有长期归档/轮替闭环。应保留交易、财务和审计历史的可追溯性。
- 签名升级协议已有，当前发行清单的正式发布者签名仍为 `NOT_CONFIGURED`。本机自行信任的升级不等于正式发行渠道已经建立。
- Windows 完整运行已验证；普通新电脑的首次安装、恢复和升级体验仍待验收。没有看到同等成熟的 macOS 完整安装产品。
- 部分旧愿景/优化文档仍将已完成模块列为未完成，或保留旧样品规则，需要统一当前能力与验收索引。

证据：`packages/a2n-sdk/src/a2n_sdk/task_quality/service.py:49`；`packages/a2n-sdk/src/a2n_sdk/task_quality/calibration.py:136`；`artifacts/A2N-desktop.manifest.json:14`。

## 5. 后期扩展，当前不作为核心闭环阻塞

- 创作者分成：包清单保存创作者与分成约定，实际分账未实现；平台零佣金仍成立。
- 更多支付协议、计量后付和更多执行后端：按实际需求扩展，现有支付协调架构已提供扩展位置。
- 自动偏好学习：可在获得真实使用反馈后增加可关闭的学习能力。

不把中央仲裁、绝对公平、全网统一封禁或支持所有支付协议列为用户必须兑现的愿景。

## 6. 建议开发顺序

1. 修复样品误脱敏，补齐自定义任务类别的页面选择。
2. 完成“表达需求 → 发现后筛选 → 比较样品 → 调用 → 评价”的普通用户流程与本机效果记录。
3. 接入少量真正有用、不同能力的 Agent，补对应的质量评审和成果展示；沿用既有交易闭环验证。
4. 在持续真实使用中完成质量校准、信誉效果验证；节点主人自行选择本地执行策略。
5. 补容量/归档/定期备份与正式发行，再扩展工作流安装、复杂媒体和后期分账。

本轮仅新增审计文档与脱敏状态快照，没有修改运行策略、支付配置或业务代码，也没有重复制造交易记录。
