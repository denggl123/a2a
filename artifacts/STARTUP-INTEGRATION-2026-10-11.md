## 修复与模块边界

| 问题 | 修复 | 实际验证 |
| --- | --- | --- |
| 保护脚本仅填总内存值，未启用整树限制标志 | 产品内独立 process_limits 模块，Windows 同时设置单进程和整树 4 GiB 限制 | 原生小额度单进程与父子合计内存回归；安装版状态确认限额生效 |
| 关闭保护句柄可能杀死升级替换进程 | 产品保护 Job 不使用 KILL_ON_JOB_CLOSE | 独立进程退出后替换子进程存活；实际桌面升级完成 |
| Windows 保护 API 在 Linux 导入即执行 | 平台判断后延迟加载原生 API | Linux 隔离容器实际启动、公共目录 200、管理控制台 404 |
| 公共入口被改为桌面入口，覆盖环境配置 | 公共服务继续使用原部署入口；桌面入口独立解析安装记录 | Linux 实际公共地址与端口核对；服务器产品文件完整核对 |
| 写死本机路径、按任意监听端口猜测进程 | 显式 home 优先；旧计划任务从原工作目录识别 home；安装程序必须匹配哈希 | 旧计划任务原动作实际执行，PID 34184 → 34184，未产生第二个节点 |
| 活体检查通过启动、终止生产进程验证限制 | 改为受保护本机 API 的只读检查 | 当前安装版实际 BUNDLED 模式、版本、哈希和限额核对 |
| 备份接口、硬编码路径及异常处理不一致 | 测试链与 facilitator 各用其正确接口；参数化路径、保留数；内容完整校验与原子发布 | 损伤 gzip、非法 JSON、磁盘失败、额度与轮转回归；现有环境只读快照通过 |

进程保护属于产品装配层，库被第三方导入时不改变其宿主的全局限额。Windows 限制模块不改动网络、交易、评价或支付策略；Linux 沿用既有产品配置。保护模块控制自身创建的 Job，不能取消外部宿主的进程终止策略。

启动与快照规则见 [工具入口](../scripts/README.md)、[支付测试备份规则](../docs/runbook-anvil-snapshot-restore.md)。
